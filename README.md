# redfront (рабочее название)

English version: [README.en.md](README.en.md)

Генератор динамической кампании для DCS World на карте Cold War Germany (Python + pydcs, скрипты миссии на Lua,
окно кампании в браузере). Полный цикл: модель кампании → план дня → миссия → вылет в DCS → дебриф → следующий день.

## Что это

Игрок выбирает сторону, а с ней поведение ИИ и логику фронта. Какой техникой летать — решает он сам.

### Три слоя

| Слой | Где | Что в нём |
|---|---|---|
| Модель кампании | `state` кампании (`camp.json`), `model.py`, `sim.py`, `ops.py`, `logistics.py` | «карты и стрелочки»: части с численностью по типам, состоянием и маршрутом; пункты, аэродромы, склады, мосты; наземная модель по часам |
| План дня | `planner.py`, `ato.py`, `command.py` | план полётов обеих сторон на сутки (ATO): задачи, пакеты, время |
| Миссия DCS | `build.py`, `materialize.py`, `redfront/lua/*.lua` | `.miz` через pydcs: окно вокруг вылета игрока и весь театр реже; скрипты миссии; хук дебрифа |

Данные, из которых строится модель:

| Данные | Файлы | Что в них |
|---|---|---|
| Доктрина стороны | `redfront/data/doctrine/<пакет>.json` | задачи, исполнители по ролям, профиль полёта, порядок марша, пороги, коэффициенты наземной модели. Пакеты: `wp` (Варшавский договор), `nato` (НАТО, синие по умолчанию), `generic` (общий профиль) |
| Состав сил | `redfront/data/oob_*.json` или свой файл | любые типы, которые знает pydcs (имя класса или DCS id), у каждой части роль; страны сторон |
| Сектор | `redfront/data/sector_*.json` или свой файл | пункты, связи, аэродромы, склады, мосты, позиции объектовой ПВО |

Связующие таблицы: `roles.json` (роли и категории: air / heli / ground / sam), `aircraft.json` (свойства типов ЛА)
и `payloads.json` (подвески по задачам из DCS Retribution).

Откуда берутся числа планировщика: радиус авиачасти — `strike_radius_km` у части, иначе у роли; радиус ЗРК —
`threat_radius_km` у части, иначе у роли, иначе наибольший `threat_range` пусковых из pydcs (это дальность по
высотной цели, против маловысотной она завышена; см. также радиогоризонт ниже).

Типы модов (Су-24, МиГ-31 и др.), которых pydcs не знает, не поддерживаются: их регистрация — отдельный шаг.

### Окно миссии и правило сохранения

В миссию подробно попадает окно вокруг вылета:

1. **район задачи** — цель разворачивается куском части по шаблону построения;
2. **коридор маршрута** — ЗРК, которые достают маршрут;
3. **остальной театр** — реже (см. [Весь театр в миссии](#весь-театр-в-миссии)).

**Правило сохранения:** развёрнутая машина несёт вес = исправные машины этого типа в модели / развёрнуто этого типа.
При любой плотности (`--density`, бюджет миссии) потери в DCS возвращаются в модель честно.

### Принципы

* **Реализм по источникам.** Механики опираются на открытые источники (ссылки — в тексте и в полях `source` /
  `method_source` данных).
* **Всё, что не из источника, — оценка.** Каждое такое число помечено: в данных — `"estimate": true`,
  `estimate_fields`, поля `*_note`; в коде и тексте — ОЦЕНКА. Составы, темпы, радиусы, подвески, высоты, порядок
  следования, коэффициенты — оценки. Координаты населённых пунктов, складов и мостов приблизительные — их стоит
  проверить в редакторе DCS.

## Установка и запуск

### Готовая программа (Windows, без Python и git)

Сборка — `.github/workflows/release.yml` (PyInstaller на Windows в GitHub Actions; перед упаковкой собранная
программа создаёт кампанию, план и миссию — проверка). Получить архив:

* релиз: поставить тег версии и отправить его — `git tag v0.10 && git push origin v0.10`; архив
  `redfront-v0.10-windows.zip` появится в Releases репозитория;
* без релиза: GitHub → Actions → release → Run workflow; архив — в артефактах прогона.

В архиве — папка `redfront` с `redfront.exe`, `README.md` и `ЗАПУСК.txt`: распаковать, запустить `redfront.exe`
(окно кампании открывается в браузере; кампании хранятся рядом с программой). Программа не подписана — Windows может
предупредить «неизвестный издатель».

### Из исходников (Windows)

Нужны Python 3.11+ (при установке отметить «Add python.exe to PATH») и Git (pydcs ставится из GitHub).
В PowerShell в папке проекта:

    py -m venv .venv
    .venv\Scripts\python -m pip install -r requirements.txt
    .venv\Scripts\python tools\smoke_test.py             # тест без DCS

`.venv\Scripts\python` вызывается напрямую: активация `Activate.ps1` не нужна (на многих системах её блокирует
политика выполнения скриптов). Окно кампании — `run.bat` (`python -m redfront gui`); первый запуск `run.bat` сам
создаёт `.venv`.

### Требования в DCS

* Карта Cold War Germany.
* **Хуку дебрифа нужен разблокированный `io`/`lfs`** в `<DCS>\Scripts\MissionScripting.lua`: закомментировать строки
  `sanitizeModule('io')` и `sanitizeModule('lfs')` (сделайте резервную копию; обновления DCS возвращают файл).
  Папка Saved Games может называться `DCS` или `DCS.openbeta` — хук пишет в `lfs.writedir()`.

## Быстрый старт: цикл дня

В окне: **Новая** (кампания) → **1. План** → **2. Миссия** → летать в DCS → **3. Дебриф** → **4. Конец дня**.

* **План** строит план полётов обеих сторон на сутки (ATO).
* **Миссия** собирает `.miz` выбранного вылета в `Saved Games\DCS*\Missions`.
* После вылета **Дебриф** находит файл хука сам (`Saved Games\DCS*\redfront`) и применяет потери, посадки,
  перемещения, разведку к модели. Часы кампании переходят на конец миссии; в плане остаются вылеты позже.
* **Конец дня** досчитывает сутки и строит новый план.

То же из консоли:

    .venv\Scripts\python -m redfront new     camp.json [--side red|blue] [--oob my_oob.json] [--sector ...] [--doctrine blue=generic]
    .venv\Scripts\python -m redfront plan    camp.json
    .venv\Scripts\python -m redfront ato     camp.json [--side own|enemy|all]
    .venv\Scripts\python -m redfront build   camp.json day1.miz [--task N] [--fly strike|sead|recon] [--humans N] [--budget N] [--density 1.0] [--ai]
    # летаете day1.miz в DCS
    .venv\Scripts\python -m redfront debrief camp.json [файл]
    .venv\Scripts\python -m redfront end-day camp.json
    .venv\Scripts\python -m redfront status  camp.json

Прочие команды: `gui [--port 8765] [--no-browser]`, `menu [кампания.json]` (текстовое меню: статус, план, сборка,
дебриф, конец дня, новая кампания — вводом номеров; также `run.bat menu`), `roads-probe`, `roads-apply`,
`map-probe`, `map-apply`, `map-import`, `set-damage` (вручную задать повреждение объекта тыла 0..1, если дебриф его не
засчитал), `set-pos` (поправить координаты объекта тыла по редактору DCS).

Параметры `new`: `--name`, `--date` (по умолчанию — дата пресета), `--seed` (повторить кампанию), `--variant NAME`
(вариант сценария), `--no-random` (без случайности), `--roads <файл>`.

## Интерфейс

Окно кампании — страница в браузере (`redfront.exe`, `run.bat` или `python -m redfront gui`).

### Раскладка окна

* **Верхняя панель** — кампания, «Новая», кнопки цикла дня, день и время обстановки; справа — кнопки панелей
  (◧ левая, ⬓ матрица, ◨ инспектор), ⚙ настройки, ? справка.
* **Слева** — вкладки списков (Вылеты, Войска, Авиация, Тыл, Журнал) и сообщения программы.
* **В центре** — карта. У выбранного вылета на ней маршрут каждой группы своим цветом, точки маршрута с временем
  (взлёт, сбор, ИПМ, цель, посадка) и зоны ЗРК коридора; условные знаки сворачиваются.
* **Справа — инспектор** выбранного: вылет (время на объекте, группы, маршрут каждой группы по точкам со временем,
  угрозы, «что даст удар», сборка миссии, «Изменить», «Снять») или объект карты (часть, ЗРК, склад, мост — по
  щелчку на знаке).
* **Снизу — матрица синхронизации**: строка на каждую группу вылета, полоса — от взлёта до посадки, ○ — сбор, ◆ — выход
  на объект, пунктир — время удара вылета, затенено — ночь, жёлтая линия — часы кампании. Метку ⇔ у своего вылета можно
  тянуть: вылет переносится с шагом 5 мин, сервер проверяет самолёты и время (не встаёт — вылет остаётся прежним, в
  сообщениях — причина). Фильтры: дежурства, прошедшие; масштаб — кнопки −/+.
* Выбор общий: вылет, выбранный в списке, на матрице или на карте, выделяется везде. Ширина панелей и высота матрицы
  меняются перетаскиванием границ и запоминаются в браузере.

### Шапка

* выбор кампании;
* **Новая** — новая кампания: театр (сектор), состав сил (пресет или «(свой)»), сторона. «Копия для правки» кладёт
  копию выбранного пресета в `presets/<имя>.json` (правится в текстовом редакторе: части — `units`, тип `type`, число
  `count`, аэродром `base`, роль `role`), после чего он появляется в списке как «(свой)»;
* **⚙ Настройки**, **?** (справка);
* кнопки цикла дня: **1. План**, **2. Миссия**, **3. Дебриф**, **4. Конец дня**.

В окне показывается время обстановки («День N, обстановка на ЧЧ:ММ»).

### Вкладки

* **Вылеты** — вылеты своей стороны из плана полётов на сутки, по времени на цели (одна карточка на вылет: «взлёт
  09:01, на объекте 09:15»). Выбранный вылет открывается в инспекторе: группы пакета, угрозы в
  коридоре, пояснения «что даст удар»; там же — в какой группе летит игрок, сколько людей в вылете, сборка миссии. **Режим командующего** (`redfront/command.py`):
  * «Изменить» — время на объекте; у каждой группы пакета часть-исполнитель (только с ролью группы и в радиусе до
    объектов; маршрут — от её аэродрома), число бортов (1–4), подвеска («по задаче» или любая подвеска DCS
    Retribution этого типа);
  * «Снять» — любой свой вылет, включая дежурства и перевозки;
  * «+ вылет» — задачи, которые планировщик нашёл, но в план не взял (лимиты плана): поставить в своё время или в
    первое свободное.

  Каждое изменение проверяется по всему плану стороны, как при его построении (самолётов хватает на всё время
  вылета плюс подготовку; ночью летят только типы, которые умеют). Правка не встала — вылет остаётся прежним, в окне
  — причина. Не слетанные игроком вылеты модель считает по новому составу и времени. План противника не правится.
* **Войска** — наземные части: свои; противника — по данным разведки.
* **Авиация** — авиачасти: экипажи, «Лётчики, ливрея», «Добавить полк» (из исторического списка или свой),
  «Перебазировать».
* **Тыл** — снабжение: запасы складов (%, т, «отрезан»), пути подвоза, сводка «Тыл за сутки» (подвоз, воздухом,
  расход, «колонны разбиты — недовезено»), «Что значат тонны» (расход, подвоз, на сколько суток запаса,
  промышленность). Запас складов противника — только оценка, без тонн.
* **Журнал** — журнал событий.

### Карта

Тактическая карта сектора (`redfront/web/tactical.js`, классификация частей — `redfront/symbols.py`):

* Подложка — бумажная (OSM, приглушённая), топографическая (OpenTopoMap) или без подложки; выбор запоминается.
* **Линия фронта** — граница территорий сторон: каждая точка карты принадлежит стороне, чей пункт или часть в поле
  ближе (диаграмма Вороного на сетке). По обе стороны границы — передний край: красная линия у красных, синяя у
  синих; территории слегка тонированы. Часть в тылу противника (десант, прорыв) — свой «островок».
* **Знаки — по стороне игрока.** За красных — по правилам рабочей карты командира Советской Армии (И.Д. Помбрик,
  Н.А. Шевченко, «Рабочая карта командира», 1967; БУ СВ ч. II, 1983): свои мотострелки, танкисты, десант и авиация —
  красным, свои ПВО и все надписи своих — чёрным, противник — синим, маршруты своих — коричневым; надписи
  горизонтально, наклонным шрифтом. Знаки техники: танк — ромб, БМП — «пуля» с чертой у кормы, БТР — «пуля»,
  транспортный вертолёт — у десанта; знаки своих направлены к противнику, ПВО — к верхнему обрезу карты.
  Оборона — замкнутый контур с черточками по переднему краю; резерв и сосредоточение — «район, занимаемый
  подразделением» (пунктир — намечен к занятию); марш — колонна на технике (черточки звена: батальон — три, рота —
  две); наступление — прерывистая стрелка; небоеспособная часть — «остановлена на рубеже», отход — знак отхода;
  десант — район высадки со знаком вертолёта. ЗРК — пусковая установка в кружке (черточки — дальность), КРУ — РЛС
  обнаружения; склад — квадрат «ГБ» (заливка — запас, пунктир — отрезан); мост и разрушенный мост —
  топографическими знаками. Подписи — сокращениями БУ («94 гв. мсд», «1 тбр 1 тд США», «2/271 пдб»), ⚠ — без
  полного снабжения. За синих — APP-6 НАТО: свои — голубые прямоугольники, противник — красные ромбы, знак рода
  войск в рамке, звено (II, X, XX) над рамкой.
* Аэродром — силуэт самолёта: действующий — залитый, закрытый или потерянный — контурный и перечёркнут; цвет — чей.
  FARP — кружок с «Т»: занятый — заливкой, свободный — контуром.
* Зоны поражения ЗРК противника — пунктиром с заливкой, свои — едва видны; данные старше 2 суток — бледно
  («устарела»). Маршрут части — ближний участок. Свои пути подвоза — слой «Пути подвоза» (толщина — поток). Свои
  сбитые экипажи — на карте.
* На мелком масштабе подписи, ЗРК и FARP прячутся; связи пунктов (граф дорог) — отдельный слой, по умолчанию выключен.

## Кампания и модель

### Оперативный уровень

Сектор — граф пунктов (`places`, `links`) с владельцами; линия фронта — связи между пунктами разных сторон.
Командование каждой стороны (`ops.py`) ставит задачи своим частям по позе из пакета доктрины:

* `offense` (красные) — свободные сильные части наступают на соседние пункты противника, ближние к цели операции
  (`objectives` сектора; на театре всей карты — 8 осей, `objectives.red`, у части — `axis`);
* `defense` (синие) — занимают незанятые пункты фронта, лишние сильные части возвращают пустые пункты.

Ослабевшие части выходят из боя, отходят в тыл и восстанавливаются; пункт занят, если рядом часть стороны и нет
противника. Резервы вводятся в свой день (`arrives_day`). Коэффициенты — ОЦЕНКИ (раздел `sim` доктрины, `ops_note`).
`status` показывает пункты сторон и линию фронта.

**Случайность.** При `new` выбирается вариант сценария (`variants` в составе сил) и разброс сроков ввода резервов; в
бою — разброс потерь, в наступлении — выбор направления с весами. Всё повторяемо по `--seed`; `--variant NAME` —
вариант явно; `--no-random` — без случайности. Коэффициенты — ОЦЕНКИ (`random_note`).

### Оперативные приёмы доктрин

Параметры — в разделе `sim` доктрины (ОЦЕНКИ по смыслу: Ионин «Тактика» 1987, Савкин 1972, Доннелли «Red Banner»
1988; FM 100-5 1982/1986, FM 71-100 1990, RAND R-3385). Решения — раз в 6 ч вместе с командованием сторон (`ops.py`).

* **Артиллерия в бою** (обе стороны): сила части ×(1 + `artillery_factor` (0,25) × доля исправных орудий батареи
  поддержки). Выбитые в миссии орудия ослабляют часть и в модели.
* **Подготовленная оборона** (обе стороны): часть в обороне без боя окапывается; после `prepared_h` (12 ч) её потери
  в бою ×`prepared_factor` (ОВД 0,75, НАТО 0,65 — упор на подготовленные рубежи). Новый маршрут — окапываться заново.
* **Форсирование с ходу:** разрушенный большой мост закрывает подвоз, но не манёвр — части идут через реку с задержкой
  (путь длиннее на `crossing_km`: ОВД 30, НАТО 40; марш на этой связи ×`crossing_slow`).
* **ОВД — передовой отряд:** сильнейшая свободная часть (боеспособность от 85%) получает рубеж в глубине
  (`forward_depth` пунктов за фронтом на пути к цели операции) и идёт быстрее главных сил (×1,5). Один на сторону.
* **ОВД — второй эшелон в полосе успеха:** прибывающие резервы вводятся не в заранее назначенный район, а у своего
  пункта фронта (не дальше 100 км от назначенного), где свои сильнее всего относительно противника; одну полосу не
  забивают все сразу.
* **ОВД — оперативная маневренная группа:** с `omg_from_day` (2-е сутки) после прорыва (пункт противника у фронта без
  его частей ближе 15 км) сильная свободная часть идёт в глубину на ближний склад или мост противника (×1,3).
  Занятый пункт со складом — склад потерян противником (подвоз от него прекращается).
* **НАТО — сдерживание (covering force):** часть в обороне против противника сильнее вдвое при боеспособности ниже 80%
  отходит на следующий рубеж, не дожидаясь разгрома.
* **НАТО — контрудар резервом:** свободная сильная часть бьёт по части противника, вклинившейся на свою территорию,
  если сильнее её в 1,2 раза и она не дальше 60 км.
* **Темп:** в журнале за сутки — занятые пункты и наибольшее продвижение частей наступающей стороны против нормы
  доктрины (`tempo_km`, ОВД ~40 км/сутки).

### Наземная модель по часам

Наземная модель (`sim.py`, коэффициенты — раздел `sim` доктрины, ОЦЕНКИ): части идут по маршрутам до соприкосновения
(`contact_km`), в соприкосновении несут потери по соотношению сил (техника с весами ролей; у обороняющейся меньше),
ниже порога боеспособности выходят из боя. Дошедшая до конца маршрута часть занимает район (оборона). Приданная ПВО
несёт потери вместе с частью.

Темп марша: вне соприкосновения (противник дальше `road_clear_km`, 15 км — рубеж развёртывания в предбоевой порядок)
часть идёт маршевой колонной — `road_march_km` в сутки (150 км, ОЦЕНКА), ближе — темпом наступления
(`daily_advance_km`, 25 км). У части можно задать свой `road_march_km` (0 — всегда темп наступления; так в учебном
сценарии «Гамбург»). В сценарии «Удар ОВД по всему фронту» (вариант `assembly`) первый эшелон ОВД стоит в исходных
районах у границы, бригады НАТО первого дня — в пунктах у границы (передовая оборона); бои — с первых часов 1-го дня
(`model.assembly_areas`). Место части в дороге (`model.unit_pos`) — по кэшу геометрии маршрута: конец суток всего фронта
считается за секунды, а не минуты.

Модель идёт за часами кампании (`sim.advance`): шаг — 1 ч, бой и марш за шаг — 1/24 суточной нормы (сила
пересчитывается каждый час), занятие пунктов — каждый час, решения командования — в 00, 06, 12 и 18 ч
(восстановление в тылу — за 6 ч). Снабжение, ремонт, пополнение, судьба сбитых экипажей — раз в сутки, в их конце.

* **Миссия видит мир на своё время.** Сборка вылета продвигает модель к началу миссии и переносит цель задачи и
  маршруты групп на место цели к этому времени (`planner.refresh`). Модель назад не идёт: вылеты раньше времени
  обстановки из плана уходят.
* **Окно слетанной миссии.** Бой и марш в нём прошли в DCS (дебриф их применил) — модель проходит это окно только
  событиями плана полётов, без боя и марша.
* **Ночь** — часы вне лётного дня (06–20). Ночью марш ×0.6, потери в бою ×0.5 (`night_march`, `night_battle`). ОЦЕНКИ.

### Бой в миссии

Миссия по войскам в соприкосновении ставит весь бой: обе стороны боевыми порядками в дальности огня друг друга, ПВО
при частях позади; потери в миссии идут в модель.

* `lua/front.lua` (идея — скрипт Troops in Contact, Grendel, MIT; код свой, без MOOSE): части стоят взводами по 4
  машины (имена машин из модели). Сами взводы огонь не ведут: скрипт даёт им короткие окна огня в точку в 25–80 м от
  случайной машины противника в дальности их оружия — бой шумный, потерь мало (их считает модель). Наступающий
  выходит на рубеж огня и при потерях в миссии ниже 60% отходит на исходную; обороняющиеся взводы понемногу
  сдвигаются. ИИ-самолёты видят цели. Числа — ОЦЕНКИ (`build.FRONT_CFG`).
* `lua/battle_site.lua` расставляет бой по местности в начале миссии (pydcs рельефа не знает): весь бой сдвигается в
  пределах 2,5 км туда, где под позициями меньше воды, склонов и застройки, затем каждая машина — в лучшую точку рядом
  (дорога > у дороги > поле > застройка; вода и склон исключены). Взводы пересоздаются с теми же именами и groupId.
  Место пишется в дебриф, модель его помнит (`battle_sites`). ПВО на позициях ставится на открытое место (поле, у
  дороги, не на дороге и не в застройке; не теснее 80 м; сдвиг до 400 м), не ближе 150 м к бетону аэродрома; позиция
  на аэродроме, в воде или в городе (5 и больше строений ближе 150 м) сдвигается целиком (до 8 км). Лес DCS скрипту
  не отдаёт. Веса — ОЦЕНКИ (`build.SITE_CFG`).
* Огонь по ЛА ведёт только ПВО (роли `sam_*`); остальные наземные группы — только по наземным целям
  (`OptRestrictTargets`, ставится в .miz и заново после перекладки колонны на дорогу). Войсковая ПВО части
  (`attached_to`) идёт отдельной группой в колонне сразу за танками.
* Позиция ЗРК развёрнута на ось угрозы (`heading_deg` у части, иначе пеленг на ближайший аэродром противника): иначе
  РЛС (например, Patriot) смотрит не туда.

### Боевые порядки и артиллерия

Часть в бою расставляется по доктрине стороны (`redfront/formations.py`; ОЦЕНКИ по смыслу уставов, расстояния ужаты
под бюджет машин): машины делятся на роты по 10 (танки и БМП в каждой роте).

* **ОВД** (Боевой устав СВ; Ионин, «Тактика», 1987): оборона — ротные опорные пункты, две трети рот в первом эшелоне
  (фронт роты 1 км), треть — во втором (1,5 км позади); наступление — роты линией (фронт роты 700 м), танки впереди,
  БМП в 150 м за ними, треть рот — во втором эшелоне.
* **НАТО** (FM 71-1, FM 71-2, 1988): оборона — ротные тактические группы на позициях уступом (интервал 1,4 км,
  уступ 600 м), машины дугой; наступление — ведущая группа клином, остальные уступом позади (прикрытие огнём).

**Артиллерия.** У каждой части в бою — батарея поддержки (6 орудий: 2С1 «Гвоздика» у ОВД, M109 у НАТО; ОЦЕНКА) в 6 км
за боевым порядком. В миссии она ведёт 4 огневых налёта по линии противника (по 24 снаряда, рассеивание 250 м).
Потерянные орудия запоминаются у части (батарея в следующих миссиях меньше) и восстанавливаются по одному в сутки.
В наземной модели артиллерия отдельно не считается — её огонь входит в потери боя.

### Сеть ПВО

`lua/iads.lua` (идея — Skynet IADS, своя реализация; величины — ОЦЕНКИ):

* **Узлы сети** — КРУ и РЛС обнаружения (наземные) и ДРЛО (А-50, E-3A) своей стороны.
* **ЗРК средней и большой дальности на связи** (живой наземный узел не дальше 150 км или ДРЛО в воздухе) держат РЛС
  выключенными, пока сеть не видит самолёт противника ближе их зоны поражения ×1,15; после последнего контакта
  РЛС работают ещё 60 с.
* **Без связи** (узлы уничтожены или далеко) ЗРК действуют сами по себе: РЛС включены всё время (ИИ DCS по умолчанию)
  и раньше раскрывают себя.
* **Пуск ПРР** в сторону ЗРК (конус ±20°, до 120 км): ЗРК с вероятностью по типу (старые — С-75, С-125, «Куб»,
  Hawk, Rapier — 0,3; «Роланд», «Оса», «Тунгуска», «Гепард», «Шилка» — 0,5) замечает ракету и выключает РЛС на время её
  полёта и ещё 120 с — это и есть подавление: удар проходит, ЗРК цел. Patriot (сбивает ПРР) РЛС не выключает.
* **Кампания:** уничтоженный КРУ остаётся уничтоженным (модель), и ЗРК его района в следующих миссиях работают без сети.
  У НАТО наземных РЛС системы NADGE в составе сил нет — узел сети синих только E-3A.

### Фронт на карте F10

В миссию (`redfront/frontline.py`, рисунки редактора миссий) на слой каждой стороны кладётся её картина обстановки на
начало миссии — тот же расчёт, что в окне программы: линия соприкосновения (красная и синяя линии по пунктам сторон и
частям в поле), своя территория лёгкой заливкой, пункты точками с подписями, цели операции своей стороны — выделены
(«◎»). Противник — по своей разведке: части, о которых известно только присутствие, линию не двигают. Линия и заливка
не рисуются дальше 45 км от пунктов и частей. Карта F10 показывает слой своей коалиции.

### Дороги

В pydcs дорожной сети нет; дороги знает только DCS (`land.findPathOnRoads`). Если модель не знает дорог участков,
по которым идёт колонна, миссия в первую секунду сама перекладывает колонну на дорогу (`lua/column_road.lua`: та же
группа, те же имена машин и groupId) и пишет найденные пути в файл дебрифа; после `debrief` модель их запоминает.
Если DCS дорогу не нашёл, колонна остаётся на месте (строка в журнале дебрифа).

Дороги всего театра сразу — служебная миссия: «Зонд дорог» в настройках или
`roads-probe <out.miz> --sector sector_germany.json --oob oob_germany.json`, запустить в DCS, затем «Применить дороги»
(или `roads-apply camp.json <roads_*.json>`, `new ... --roads <файл>`). Новая кампания берёт дороги сама: из Saved
Games (`redfront\roads_<сектор>.json`), иначе из поставки (`redfront/data/roads_<сектор>.json`, если файл есть).
Дорогу длиннее 2 × прямой + 15 км (DCS иногда даёт путь с крюком) модель не берёт — участок по прямой. Граф пунктов
меряется по длине дорог, где они известны.

### Тыл: аэродромы, склады, мосты

* Только военные аэродромы (список в файле сектора, по памяти о базах 1980-х — проверить). Противник ближе 30 км —
  аэродром закрыт, эскадрильи перебазируются на ближний открытый свой; противник на аэродроме — потерян (к
  противнику не переходит). Повреждение аэродрома — меньше самолётов к вылету. Эскадрильи пополняются до штата.
* Мосты на связях: разрушенный закрывает связи на 3 суток.
* Цели в миссии — объекты карты в районе объекта (`lua/targets.lua`, как «Assign as» в редакторе): их гибель пишет
  хук, дебриф переводит в повреждение. Коэффициенты — ОЦЕНКИ (`logistics_note`, `debrief.FULL_DAMAGE`).
* Коалиция аэродромов в миссии — по модели: военные аэродромы сторон — их коалиции, потерянный и прочие —
  нейтральные. Склады аэродромов DCS — безлимитные.

#### Объекты тыла на карте DCS

Координаты складов и мостов — ОЦЕНКИ; их нужно привязать к реальным объектам карты: «Зонд карты» (`map-probe`) —
служебная миссия, находящая объекты мостов и складов сектора; «Применить зонд» (`map-apply` к кампании или к файлу
сектора); импорт `.miz` с зонами «Assign as...» (`map-import`, ROLE = depot|bridge, VALUE = id объекта); `set-pos`.

### Снабжение в тоннах

Одна величина — «снабжение», т (топливо и боеприпасы вместе). Все числа — ОЦЕНКИ (`supply_t_note`, раздел `sim`):

* **Склад** — запас `stock_t` из ёмкости `cap_t` (ёмкость складов стороны — `depot_days` = 10 суток её расхода в
  обороне, поровну). Повреждение склада уничтожает запас сверх ёмкости × (1 − повреждение).
* **Расход** части в сутки — исправные машины (с приданной ПВО) × `consume_t` по состоянию: бой 1.0 т, марш 0.5,
  восстановление 0.3, оборона 0.2 т на машину. Часть берёт со своих складов не дальше `supply_km` по своей
  территории; бой — первым. Получила долю нормы — сила между `supply_power_factor` и 1, марш — между `unsupplied` и 1.
  Авиация — `sortie_t` (4 т самолёт, 1.5 т вертолёт) на вылет, со склада, до которого от аэродрома есть путь;
  аэродром без снабжения выпускает меньше самолётов.
* **Подвоз из тыла** — `supply_inflow` = 2.5 × расход стороны в обороне в сутки: марш держится, бой съедает склады.
  Только на склады, до которых есть путь от пунктов входа (`supply_entry` сектора или 3 своих пункта, дальних от
  фронта). Отрезанный склад (окружение, разрушенные мосты) получает снабжение только воздухом.

#### Пути подвоза и колонны снабжения

Подвоз идёт к каждому складу по своему пути — от ближнего пункта входа по своей территории, по дорогам
(`convoys.py`). Поток пути — сколько склад недополучил после расхода суток (в пределах подвоза стороны), т/сутки;
поток участка — сумма путей через него; грузовиков — поток / 8 т.

* **В миссии** на участках с потоком от 30 т/сутки ближе 40 км к цели идут колонны грузовиков обеих сторон (Урал /
  КамАЗ, M818 / Bedford / Land Rover): 4–16 машин — доля суточного потока на участке во время миссии (10%), по дороге
  к концу участка. Машина несёт вес — грузовиков потока на машину.
* **Удар по путям подвоза** (`strike_supply_route`, обе стороны, до 2 в сутки): участок с наибольшим потоком в
  радиусе; пакет — как у удара.
* **Итог.** Сожжённые машины — недовоз: вес × 8 т; удар ИИ вне миссии удаётся с вероятностью 70% минус 10% на ЗРК в
  коридоре и даёт недовоз 15% суточного потока участка. В конце суток недовоз ложится на склады, чьи пути идут через
  участок.

#### Воздушные перевозки

Задача `airlift` транспортной авиации (роли `transport`, `transport_helo`); самолётом — только ИИ, вертолётом —
может лететь игрок (груз — ящики CTLD):

* склады ниже 90% запаса со своим аэродромом не дальше 40 км, отрезанные первыми; до 4 направлений, по 2 рейса в
  сутки;
* груз — только из тыла к фронту: аэродром отправки не вертолётная площадка и хотя бы на 10 км дальше от
  противника, чем аэродром назначения;
* груз борта — `cargo_t` в `aircraft.json` (Ан-26 5.5 т, C-130 19, Ми-8 4, Ми-26 20, CH-47 10 ...);
* рейс в окне миссии — в миссии (до 2 на сторону): задача DCS Transport; сбитый борт груз не довозит;
* рейс игрока довозит то, что он доставил ящиками CTLD (ведомые ИИ — полный груз, если не сбиты).

Объёмы перевозок малы рядом с подвозом по дорогам (десятки–сотни тонн против тысяч): они решают там, где дорог нет.
Склад без своего аэродрома в 40 км воздухом не снабжается. ОЦЕНКИ.

#### Пояснения для игрока

`redfront/explain.py` — строки «что это / на что влияет / что даст удар» по тем же формулам, что и модель тыла:

* путь подвоза — сколько это грузовиков в сутки, какая доля подвоза противника, на какие склады, недовоз при удаче;
* склад — ёмкость (разведка), запас (по оценке, четвертями), кто с него снабжается, сколько сгорит при повреждении;
* завод — множитель промышленности стороны сейчас и после разрушения (ремонт тыла, пополнения);
* мост — какие связи закрывает, сколько по нему везут, срок ремонта; аэродром — кто базируется;
* наземная часть — состояние, боеспособность (по разведке), порог выхода из боя; перевозка — груз за рейс и его
  доля в расходе;
* итог удара (дебриф и удары ИИ): сгоревший запас (свой — точно, противника — по оценке), промышленность до и
  после, самолётов к вылету до и после.

### Туман войны и разведка

**ЗРК противника** (`redfront/intel.py`): игрок знает не где ЗРК стоит, а где его видели последний раз. В начале
кампании известны все позиции (разведка мирного времени); после вылета позиции ЗРК противника не дальше 60 км от
маршрутов пакета игрока уточняются. По известным позициям — карта, угрозы в коридоре и рубежи подавления ПВО; миссия
ставит ЗРК туда, где он на самом деле. Противник планирует по настоящим позициям.

**Наземные части противника** — по журналу разведки (ОЦЕНКИ):

* источники: разведка мирного времени (в начале — все части на местах, кроме резервов из глубины); соприкосновение
  (в бою или ближе 10 км к своим — видны всегда); вылет игрока (части не дальше 15 км от маршрутов пакета);
  разведывательные вылеты;
* давность: до 12 ч — точно; до 48 ч — примерно (бледнее, «?», пунктирный круг — куда могла уйти: ~1.2 км/ч на
  марше, 0.5 км/ч на месте); старше — только присутствие («??»). Давние данные линию фронта не двигают;
* цели задач — только известные части: колонна на марше — по данным не старше 12 ч, стоящая — и по примерным;
  колонну, замеченную на марше не раньше 18 ч назад, ведут счислением пути;
* удары своих ИИ вне миссии: цель в 5 км от точки — находят; дальше 20 км — «цель не найдена»; между — успех падает.

**Смена позиций ЗРК** (`redfront/samroam.py`, ОЦЕНКИ). Двигаются только самостоятельные позиции (приданная ПВО идёт с
частью, объектовая стоит). Подвижность — по самому медленному комплексу:

| Подвижность | Комплексы | Переезд в сутки у фронта | Пауза | Шаг | Район |
|---|---|---|---|---|---|
| высокая | Оса, Стрела, Тунгуска, Гепард, Роланд, Чапарэл | 0.5 | 1 сут | 3–6 км | 12 км |
| средняя | Куб, Бук, Хок | 0.3 | 2 сут | 4–8 км | 20 км |
| низкая | Пэтриот, С-75, С-125, С-200 | 0.08 | 5 сут | 5–10 км | 25 км |

Вероятность полная ближе 40 км от противника и падает до нуля к 150 км. Новая позиция — в пределах района и не
ближе к фронту. После потерь подвижный ЗРК на следующие сутки уходит на `sam_relocate_km` в тыл.

### Вертолётный десант

Десантные роты (роль `air_assault`): три роты 35-й одшбр у красных, две роты Fallschirmjägerbataillon 271 у синих —
ОЦЕНКИ (рота — 100 человек, в миссии — 24 фигуры). В резерве (`order reserve`) рота стоит в своём пункте.

Задача `air_assault` (одна в сутки на сторону; игрок может вести её на Ми-8 или UH-1H):

* **Куда.** Пункт противника в 8–50 км от своих, не соседний со своими, без его частей ближе 10 км. Лучший — тот,
  после взятия которого у противника больше всего складов отрезано от подвоза, затем ближний к цели своей оси.
  Площадка — в 2 км от пункта в сторону своих. Площадку, к которой в коридоре больше одного ЗРК (`max_threats`),
  ИИ не выбирает.
* **Чем.** Бортов = ceil(100 / десантников на борт) (`troops`: Ми-8 24, Ми-26 80, CH-53 37, CH-47 33, UH-1H/UH-60
  11), не больше 8; группы по 4 борта, вторая волна — через минуту.
* **В миссии.** Вертолёты идут на малой высоте, садятся на площадку на 2 мин и уходят. Площадка в начале миссии
  переносится на ближайшее открытое место (`lua/lz.lua`: суша, без строений ближе 45 м, перепад не больше 4 м на
  20 м; кольцами до 1.5 км). Каждый борт высаживает свою долю фигур (`coalition.addGroup`, имена из модели; борт ИИ —
  сев ближе 800 м к площадке; игрок — через CTLD).
* **Итог** (`assault.resolve`): игрок — по дебрифу; ИИ — сбитые плюс 15% на борт за каждый ЗРК в коридоре. Доля
  роты в сбитых бортах гибнет. Долетело меньше 40% — высадка сорвана, иначе рота держит пункт (`order airhead`):
  занимает его, если рядом нет противника, без снабжения слабеет. Пункт связан со своими складами — рота соединилась
  со своими.

Ограничения: лес при выборе площадки не учитывается (DCS отдаёт скрипту только строения); группы ИИ чужой задачи в
окне миссии летят и садятся, но пехота у них не выходит.

### Эвакуация десанта

Задача `air_evac` (по приоритету — сразу после CSAR): рота в тылу противника (`order airhead`), не соединившаяся со
своими, вывозится, если боеспособность ниже 50% (`evac_below`) или она держится 3 суток и больше (`evac_days`).
Площадка — в 1 км от пункта к своим; бортов — по числу живых (`troops`), не больше 8; больше 1 ЗРК в коридоре — не
летят. ОЦЕНКИ.

* **В миссии** рота стоит у площадки группами по вместимости борта (`lua/evac.lua`). Борт ИИ забирает группу сам;
  игрок — CTLD: Troop Transport → Unload / Extract Troops (группа в 125 м). Сбит борт — его группа погибла.
* **Итог** (`assault.evac_resolve`): вывезено хоть сколько-то — рота в резерве у аэродрома группы, остальные
  потеряны (плен); никого — рота держится дальше.

### Сопровождение вертолётных задач

Десант, эвакуация и CSAR идут с ударными вертолётами (`escort` у задачи): пара, звено — если транспортных больше 4.
Прикрытие выходит на площадку за 2 мин до посадки, ищет и поражает наземные цели в 3 км и держит район, пока
транспортные на земле (+2 мин). Ближняя часть ударных вертолётов в радиусе (не та, что везёт); нет — без прикрытия.
ОЦЕНКИ.

### CTLD

[DCS-CTLD](https://github.com/ciribob/DCS-CTLD) 1.6.1 с MIST из его поставки входит в миссию, только если он нужен
вылету игрока. Настройка — `lua/ctld_cfg.lua`; меню и сообщения CTLD — оригинальные (английские). Используется:

* **Десант игрока.** Зона погрузки (800 м) у стоянки игрока с группой «Assault: <рота>» (доля роты на его борту).
  F10 → CTLD → Troop Transport → Load; на площадке — Unload / Extract Troops (сесть или зависнуть для высадки по
  тросу). Высадка ближе 800 м к площадке засчитана: группа CTLD заменяется долей роты из модели. Дальше — не
  засчитано, группу можно забрать и высадить снова.
* **Перевозка снабжения** (вертолёт, `airlift`): у стоянки — машина тыла, F10 → CTLD → Crates → Supply — ящики по
  1000 кг (лёгкому вертолёту — по 500), до грузоподъёмности борта. Сдать — на аэродроме назначения (зона 2.5 км):
  сбросить или распаковать. Доставленные килограммы — в дебриф и в конце суток на склад.
* **Авианаводчик** (задачи с `jtac`: удар по войскам в соприкосновении, боевые вертолёты): пост (УАЗ-469 / Hummer,
  невидим для ИИ противника) у своего взвода, ближнего к цели, на 300 м дальше от неё. Подсвечивает цели лазером
  (код 1688) и ставит дым; F10 → JTAC Status.

Выключено то, чего нет в модели: FOB, ЗРК и техника из ящиков, маяки, разборка техники. Свой код — CSAR (в CTLD
его нет) и посадка/высадка десанта ИИ (`lz.lua`, `assault.lua`).

### Передовые вертолётные площадки (FARP)

Готовые площадки карты Германии («H FRG nn», «H GDR nn»; медицинские и радарные — нет) — базы модели
(`redfront/farp.py`). Чья площадка — по владельцу ближнего пункта; противник ближе 15 км — закрыта, ближе 3 км —
потеряна. Каждые сутки вертолётные части выдвигаются на свою открытую площадку в 15–50 км от противника, если она
хотя бы на 25 км ближе к фронту, чем основной аэродром, и не дальше 150 км от него; одна часть — одна площадка
(ОЦЕНКИ, `farp_*` в `sim`).

Площадка принимает от звена (4) до эскадрильи (12) — ОЦЕНКА: на неё выдвигается передовая группа (отдельная часть
«..., передовая группа» с долей экипажей и лётчиков), остальные остаются на аэродроме. Площадка закрыта, потеряна
или фронт подошёл — группа возвращается (снова — не раньше следующих суток). Снабжение — как у аэродрома.
Самолёты на площадки не перебазируются. В миссии вертолёты взлетают с площадки и садятся на неё. Часть,
перебазированная командующим, сама на площадки не выдвигается, пока её аэродром цел.

### Экипажи, лётчики и CSAR

**Экипажи.** У авиачасти `crews` экипажей (штат — 1.2 на самолёт, `crew_ratio`); к вылету — не больше экипажей.
Пополнение — 1 экипаж в сутки до штата (`crews_per_day`). Самолёт сбит:

* без катапультирования — экипаж погиб;
* катапультировался — экипаж на земле (`downed`: точка, маяк ADF 200–1190 кГц). На своей территории выходит к своим
  на следующие сутки; на чужой — каждые сутки в плен с вероятностью 35% (`capture_per_day`), через 3 суток — пропал
  без вести;
* подобран вертолётом и доставлен на свой аэродром — снова в полку.

**Лётчики** (`redfront/pilots.py`): у каждой авиачасти — список лётчиков по числу экипажей; имена вымышленные, звания
— по национальности части (СССР, ННА, ФРГ, США, Великобритания, Канада, Бельгия, Нидерланды — по названию части или
полю `nation`). В миссии имя ЛА = звание и фамилия, ведущий — старший. Сбитый — вне списка до спасения, погибший или
пленный выбывает, пополнение — новые имена.

**Ливрея полка** — «Авиация» → «Лётчики, ливрея»; для всех групп полка во всех миссиях. Список — из установленного
DCS (pydcs сканирует папки ливрей DCS и Saved Games); DCS не найден — имя папки вручную.

**Задача `csar`** (самая срочная, до 2 в сутки): свой экипаж не на своей территории, ближняя вертолётная часть в
радиусе. Игрок может лететь на Ми-8 или UH-1H; вылет ИИ вне миссии удаётся с вероятностью 70% минус 15% за ЗРК в
коридоре.

**В миссии** (`lua/csar.lua`, в каждой миссии):

* экипажи на земле из модели (в районе задачи — обеих сторон) и катапультировавшиеся в этой миссии; бессмертны и
  невидимы для ИИ — плен решает модель; пилот переносится на ближайшее открытое место (`lz.lua`, до 800 м);
* маяк ADF (AM, кГц); частоты — в задаче, в меню и в окне;
* вертолёт ближе 3 км — «слышу вас»; сесть ближе 300 м — пилот бежит к вертолёту; или зависнуть ниже 20 м на 10 с —
  лебёдка; на борту — на свой аэродром. Вертолёт сбит с ним на борту — погиб;
* меню F10 «CSAR»: список экипажей (пеленг, дальность, частота), ракета, дым у ближнего.

### Итог вылета и ИИ DCS

* **Небоевые потери вертолётов ИИ при посадке в поле не засчитываются.** Хук пишет попадания оружия
  (`S_EVENT_HIT`); вертолёт ИИ на задаче с посадкой вне аэродрома (десант, эвакуация, CSAR), потерянный без
  попадания (деревья, склон), остаётся в строю. Самолёты и прочие вертолёты, разбившиеся без попадания, — потери.
* **Итог десанта и эвакуации игрока** — что сделал он сам; доля ведомых ИИ и остальных групп пакета — по модели (не
  сбит огнём — свою долю высадил или вывез).
* **Вместимость — по типу ЛА** (`aircraft.json`: `troops`, `cargo_t`): Ми-8 — 24 солдата и 4 т, Ми-24П — 8 и 1.5 т,
  UH-1H — 11 и 1.5 т; AH-64A, SA342M — никого. Десант, эвакуацию и CSAR может вести и полк боевых вертолётов, если
  его тип возит людей.
* **Люди в вылете** — «людей N» в карточке (`build --humans N`). Места заполняются с группы игрока, затем ведущие и
  ведомые остальных групп пакета; больше одного человека — места Client (мультиплеер). Группы с людьми — холодный
  старт; итог людей — их, ИИ — по модели.

### Весь театр в миссии

В миссии — весь фронт: район задачи подробно, остальное реже (`materialize.theatre`): бои — боевыми порядками (свой
`front.lua` и место для каждого боя), колонны — на дорогах, части в обороне и в тылу — позициями, ЗРК — полностью.
Плотность вдали — 0,35 бюджета колонны, машина не «дороже» 3 машин модели (ОЦЕНКИ: `FAR_DENSITY`, `MAX_WEIGHT`). На
театре всей карты: части ближе 60 км — частично (до 24 машин), дальше — знаком присутствия (4 машины); ПВО объекта —
ближе 100 км от цели (`materialize.SAM_KM_ROLE`), остальные ЗРК — ближе 250 км: до 150 км позицией целиком, дальше —
знаком (РЛС и 2 пусковые, вес пусковой — до 3 машин модели; `SAM_FULL_KM`, `SAM_TOKEN_LN`). Войсковая ПВО частей
дальше 60 км от цели (не в бою) в миссию не ставится; в приданной ПВО вне окна задачи машин с РЛС (ЗСУ, Оса, Роланд,
Гепард…) не больше 2 (`AD_RADAR_MAX`), остальное — ПЗРК, ЗРК с оптикой, пушки. Пусковые объектовых ЗРК — по штату
(С-75 и С-200 — 6, С-125 и Куб — 4, HAWK — 6, Patriot — 8), расстановка — по системе (`SITE_LAYOUT`: «звезда» С-75,
полукруг С-200, ПУ HAWK впереди РЛС, Patriot — веером позади; ОЦЕНКИ). Пузырь: в миссию ставятся все ЗРК
противника не дальше `settings.bubble_km` (150 км, ОЦЕНКА) от маршрутов пакета, даже если не достают маршрута —
группа подавления на них не назначается.

#### Бюджет миссии

Наземных машин в миссии — не больше бюджета (по умолчанию 600, ОЦЕНКА; в настройках или `build --budget N`,
запоминается в кампании; 0 — без ограничения). Окно задачи игрока не трогается. Остальное — по удалённости от
маршрутов и объекта, дальние первыми: сначала колонны и боевые порядки прореживаются (вес машины до 3 машин модели),
затем дальние группы убираются целиком. Убранное живёт в модели. Без бюджета миссия театра к 8-му дню — до ~1200
машин.

ЛА в миссии — не больше `settings.mission_air` (в настройках или `build --air N`; 0 — без ограничения, по умолчанию).
Пакет игрока ставится всегда; затем по очереди: дежурства в зоне (ДРЛО, заправщик), пакеты ИИ (целиком, ближние к удару
игрока первыми), дежурные пары ПВО, разведка и перевозки — пока вылет помещается. План полётов лимит не меняет: вылеты,
не попавшие в миссию, летают в модели (итоги — как у всех вылетов ИИ вне миссии). Дежурство — одна смена на зону: та,
что дольше всех на станции в окне миссии, держит зону до конца миссии (смена смен — за кадром).

#### Погода и планшет

Погода — по суткам, с памятью (`weather.py`): тип (антициклон, фронт, циклон, тыл циклона) — по вероятностям смены от
вчерашнего с поправкой на сезон; облачность — пресеты DCS, нижняя граница внутри пресета; ветер у земли, на 2000 и
8000 м (сильнее и правее с высотой), температура к часу вылета (суточный ход), QNH, видимость, дождь, утренний туман
при антициклоне в холодное время. Климат — по нормам Ганновера (DWD 1961–1990), вероятности и пороги — ОЦЕНКИ.
Сводка (в духе METAR) — в брифинге, на планшете и в верхней строке окна.

Погода в плане полётов (`weather.blocks`, минимумы `weather.MINIMA` — ОЦЕНКИ): вертолёты — облака не ниже 150 м,
видимость от 1,5 км; удар с визуальным поиском цели (колонна, объект, площадка, поиск и спасение) — от 600 м и 5 км;
фоторазведка — от 1000 м и 5 км; всепогодные типы (aircraft.json `night`: Су-24М, Tornado и др.), истребители,
ДРЛО, заправщики и перевозки — по минимуму аэродрома (60 м, 800 м). Проверка — на взлёте и на выходе на объект; вылет
сдвигается на позднее время (утренний туман рассеивается к 10–11 ч), не нашлось окна — отменяется (в журнал и в окно).
Нижняя граница облаков при циклоне — 150–500 м примерно в каждый седьмой день (ОЦЕНКА). Настройки погоды (окно ⚙ → «Кампания», действие `setweather`): по климату и сезону (по умолчанию), только хорошая
(антициклон и тыл циклона, без тумана, облака не ниже 1200 м — например, для полётов на вертолётах) или заданная
(тип погоды на все сутки и утренний туман); флажок «погода влияет на план полётов» — `settings.weather_effects`.
Дата начала кампании задаётся при создании (по умолчанию — дата пресета) и меняется потом там же (`setdate`): от неё
сезон погоды и дата миссий, состав сил остаётся по пресету. После смены погода пересчитывается: если в эти сутки ещё
не летали — с сегодняшних (план полётов строится заново), иначе с завтрашних.

Наколенный планшет (`kneeboard.py`, нужен Pillow): страницы для типа ЛА игрока — задание (цель, угрозы, пакет,
порядок действий, маршрут с временем и высотой точек), связь, погода и аэродромы. DCS показывает планшет по типу ЛА,
поэтому страницы подписаны группой.

#### Скорость и страны

Скорость группы на маршруте и в расчёте времени — `speed_kmh` задачи доктрины (ОЦЕНКИ); у точки посадки — та же
скорость (pydcs ставит 0, и ИИ на возврате гасил бы скорость). Страны в миссии — Combined Joint Task Forces Red /
Blue (в них есть вся техника); национальность частей — в составе сил (`countries`), для модели и брифинга.

## Воздушная война

### План полётов на сутки (ATO)

`redfront/ato.py`: план полётов обеих сторон на лётный день (06:00–20:00, `settings.flying_hours`, ОЦЕНКА).

* Задачи стороны по приоритету доктрины ставятся по лётному дню; вылет ставится, только если у части хватает
  самолётов на всё время вылета плюс подготовку к повторному (`turnaround_min`, по умолчанию 90 мин), иначе позже,
  шагом 15 мин.
* Удары по позициям ЗРК ставятся раньше ударов по целям, которые эти ЗРК прикрывают (в коридоре или достают до цели):
  удар по цели — не раньше чем через 30 мин после удара по ЗРК (`ato.SAM_FIRST_MIN`, ОЦЕНКА). Группы обеспечения
  (прикрытие, подавление ПВО) расходятся по частям по их загрузке за сутки.
* До 40 задач стороны на сутки (`ATO_MAX_TASKS`), не больше 8 одного вида (`ATO_PER_KIND`); виды чередуются (первая
  каждого вида, затем вторая...), чтобы авиация не ушла целиком на один вид задач. ОЦЕНКИ.
* Дежурства (ДРЛО, заправщик, QRA) — сменами по 4 ч (`shift_h`); не хватает самолётов — в дежурстве разрыв.
* Исполнитель — сначала пригодный и менее загруженный тип и полк (см. [Пригодность типа](#пригодность-типа-ла-для-задачи)),
  затем ближний: вылеты расходятся по типам и полкам.
* Нет угроз ЗРК в коридоре (с учётом радиогоризонта) — переход и отход на `medium_alt_m_agl` (4000 м, ОЦЕНКА), выше
  МЗА и ПЗРК; есть угрозы — на малой высоте.
* **Ночь.** Ночью летают только типы с `night` в `aircraft.json` (Су-24М, Tornado, F-15/16, F-4E, МиГ-25/29, ДРЛО,
  заправщики, транспорт, AH-64A; Су-25, Су-17, МиГ-21/23/27, A-10A, AV-8B, Ми-24, SA342M — нет). Дежурства таких типов
  — круглые сутки; до 3 задач стороны — вечером (после 20:00, посадка до 24:00): младшие по приоритету глубокие
  удары и десант, где все группы летают ночью. В плане — 🌙, в брифинге — «НОЧНОЙ ВЫЛЕТ». ОЦЕНКИ.

**Миссия.** Начинается в своё время суток (холодный старт до взлёта по плану), окно `ato.MISSION_LEN_S` (75 мин,
ОЦЕНКА). В ней — вылеты обеих сторон, которые в это окно в воздухе: своих не больше 3 групп, противника — 4
(`build.AI_FLIGHTS`), ближние по времени и месту к удару игрока; дежурства — все. Кто к началу уже летит — в воздухе
на своём маршруте, кто позже — взлетает по расписанию. Если у одной стороны в миссии ЛА меньше 0.6 от другой
(`build.BALANCE`, ОЦЕНКА), сверх лимита добавляются её вылеты из окна. Самолёты эскадрилий сверх наличия не
расходуются.

**Вне миссии** (`airwar.py`): каждый вылет плана даёт итог в своё время на цели. Удар ИИ по колонне, части в бою,
позиции ЗРК, объекту тыла: удача — 70% минус 10% на ЗРК в коридоре (× 0.6 + 0.4 × пригодность типа); потери цели —
4% техники на пару (позиция ЗРК — 25%), объекту тыла — повреждение 25–50%. Группа теряет борт с вероятностью 3% на
ЗРК коридора; экипаж катапультируется (70%) — у цели, его можно спасать. Группы ИИ, бывшие в слетанной миссии
(`played`), итога вне миссии не получают. ОЦЕНКИ.

План: вкладка «Вылеты»; в консоли `ato camp.json`, `--side enemy` / `--side all` — план противника (отладка).

### Пакеты (тактическая группа)

Задача ставится тактической группой («Тактика ВВС» 3.3.3): ударная группа и группы обеспечения из пакета доктрины
(`strike` и `support` у задачи). Исполнители — по ролям, числу самолётов и радиусу. Игрок по умолчанию — ведущий
ударной группы (своим звеном до 4 ЛА командует сам); другая группа — в карточке или `build --fly sead|recon`.
Основная задача DCS — первая из списка доктрины, которую тип умеет (у Су-25 нет SEAD — будет Ground Attack).

**Состав групп** (`size`, ОЦЕНКИ): ОВД — удар по объекту, по колонне, по ЗРК — звено (4), свободная охота на путях
подвоза — пара, НАП — звено штурмовиков, прикрытие удара по аэродрому — звено, подавление ПВО — две пары; НАТО —
удары по объектам и BAI/FOFA — 4-ship, вооружённая разведка путей и CAS — пары, прикрытие ударов в глубину — звено.
Не хватает исправных ЛА — группа меньше.

**Сбор и порядок действий.** Группы с разных аэродромов собираются в точке сбора («Сбор», `package.rv_km`, по
умолчанию 40 км до ИПМ ударной группы на линии её аэродром — ИПМ, над своей территорией), каждая к своему времени:
ИИ приходит по ETA, игроку время сказано в брифинге. Из точки сбора группы выходят по упреждениям (`lead_min`):
подавление ПВО — первым (на рубеж пуска напрямую, без сбора), затем доразведка и прикрытие, удар — последним (T). В
брифинге — «Порядок действий группы» (T-4, T-3, T+0). Время удара назначается по самой медленной группе: группа,
которая иначе не успела бы, взлетает с началом миссии, остальные — позже; игроку — «ВЗЛЁТ через N мин» (слот доступен
с начала миссии; взлетел раньше — ждать в точке сбора).

**Профиль.** Все точки маршрута внутри известных зон ЗРК — на `low_alt_m_agl` (50 м). Ударная группа, доразведка и
подавление ПВО — с запретом сброса подвески. Скорость колонны для прогноза — замеренная в прошлых миссиях
(`observed_kmh`); без замера колонна считается стоящей. ИИ DCS ниже 100 м разбивается в разворотах, поэтому для
самолётов ИИ действует ограничение `AI_LOW_MIN_M` (вертолётов не касается). Числа — оценки (`estimate_fields`).

**Угроза в коридоре.** Радиус ЗРК — не больше радиогоризонта его РЛС по цели на высоте маршрута (50 м: ~42 км при
антенне 10 м, без рельефа): иначе С-200 или Patriot «доставали» бы любой маловысотный маршрут.

### Группы обеспечения ОВД

«Тактика ВВС» 3.3.3; составы и времена — ОЦЕНКИ; в миссии — только то, что есть в DCS.

* **Подавление ПВО — пара ПРР и пара добивания.** Пара с ПРР (Су-24М, Су-17М4, МиГ-27К) ждёт на рубеже пуска; через
  2 мин пара добивания другого типа (Су-17М4, МиГ-27К, Су-25 с кассетами и НАР) выходит на тот же рубеж и атакует ЗРК.
  Обязательна, если в коридоре есть ЗРК: без неё удар не ставится.
* **Рубеж пуска ПРР** — `min(standoff_km, дальность обнаружения РЛС ЗРК − detect_margin_km)` от места, где ЗРК будет к
  приходу группы (ПРР наводится на излучение). Подход на предельно малой высоте, на рубеже — круг ожидания (центр
  отодвинут к базе на `orbit_radius_km`) на `launch_alt_m` до времени удара + `hold_after_min`, с EngageGroup: РЛС
  войсковой ПВО в DCS включаются при подходе ударной группы. Рубеж внутри зоны поражения — ожидание на малой высоте.
  Подавление и добивание — с противоракетным манёвром (EvadeFire).
* **Связь с разведкой.** Позиция ЗРК известна точно (данные моложе 12 ч; войсковая ПВО — по данным о её части;
  объектовая — известна) — пуск по группе ЗРК. Данных нет или старые — поиск и поражение ПВО в районе (радиус —
  неточность места + 5 км). Вне миссии подавление снижает потери ударной группы от ЗРК коридора до 0.5 (свежие
  данные) или 0.75 (поиск).
* **Доразведка** — если цель на марше.
* **Расчистка воздуха** (удары по аэродромам, складам, заводам, мостам при истребителях противника) — пара МиГ-29
  выходит в зону на подходе к ИПМ за 6 мин до удара и держит её до выхода ударной на цель; зона — вне известных ЗРК,
  6000 м.
* **Прикрытие** — зона 40 км над целью на 3000 м на время удара + 5 мин, если истребители противника достают до цели.
* **Демонстративная группа** (удары по аэродромам, складам, заводам при ЗРК в коридоре) — пара на 6000 м (выше Roland
  и Gepard) другим направлением (40° от линии на ИПМ, точка вне известных зон ЗРК) за 6 мин до удара, 6 мин в районе.
* Постановщиков помех (Як-28ПП, Су-24МП, Ми-8ППА) нет — их нет в DCS.

**Вылеты ИИ в миссии — полным пакетом:** ударная группа и группы обеспечения (подавление ПВО, добивание, прикрытие,
расчистка, демонстрация) со своим временем по плану полётов; группа подавления — если её ЗРК развёрнуты в миссии.

**Удар по готовности подавления ПВО** (`lua/push.lua`). Ударная группа ИИ (пакета игрока и каждого вылета ИИ, у каждого — свой флаг) ждёт на ИПМ (круг), пока группа подавления
не начнёт пуски; пусков нет к расчётному времени + 3 мин (РЛС молчат) — удар по сроку; группы подавления сбиты, не
выстрелив, — удар отменяется.

### Подавление ПВО у НАТО

**Hunter-killer.** Пара поиска с ПРР — 52-е крыло (Шпангдахлем, F-4G; в DCS F-4G нет — F-4E: с 1985 — с HARM на
пилонах Shrike, подвеска из файла миссии работает и у игрока, в том числе на серверах с проверкой целостности; до

GR.1 RAF с ALARM (в DCS — GR.4), без пары добивания. Постановщиков помех (EF-111A, EC-130H) нет. Годы и состав —
ОЦЕНКИ.

### Вертолёты

* **Удар вертолётов по войскам в соприкосновении** (`cas_helo`): 220 км/ч, переход на 60 м, атака с 30 м, ИПМ в 8 км;
  маршрут ниже 100 м и у ИИ. Можно лететь самому (Ми-24П, SA342M).
* **Ударные вертолёты — звеном (4):** Ми-24П у ОВД, AH-64A и PAH-1 (SA342M) у НАТО. При AH-64A — пара
  разведчиков-наводчиков SA342 (OH-58 того времени в DCS нет) выходит к цели на 3 мин раньше, огонь — только в ответ.
* **Совместный удар** (`joint_heli`; НАТО — JAAT, ATP-27(C) 401.4; ОВД — Ми-24 с Су-25): удар вертолётов и удар
  самолётов (НАП, удар по колонне, BAI) по одной цели сводятся в один пакет; вертолёты на цели за 2 мин до самолётов.
* **Ночь:** из ударных вертолётов ночью летает только AH-64A.
* **Налёт** (обе стороны; FM 101-20, 1984, табл. 1-5): вертолётная часть в плане суток налетает не больше число ЛА ×
  часы в месяц / 30 (UH-1H 79, UH-60A 76, OH-58 68, AH-1 65, CH-47 58, CH-54 43 ч/мес; без строки — по аналогу,
  остальным 65 — оценка: советских норм нет).
* Сопровождение транспортных — см. [выше](#сопровождение-вертолётных-задач).

### Истребители, прикрытие войск, QRA

* **Прикрытие войск** — пара в зоне над своими частями в бою или на марше, 25 мин; можно лететь самому.
* **Дежурство ПВО (QRA)** — задача `qra` (обе стороны, только ИИ): дежурит звено (4) на 5 аэродромах вдоль фронта, не
  ближе 80 км друг к другу (`qra_bases`, `qra_spacing_km`); только части с ролью истребителя/перехватчика (или типом,
  годным для боя в воздухе), у которых после дежурства остаётся ещё звено; сменами по 4 ч.
  * **В миссии** звенья с базой не дальше 300 км от цели стоят с запущенными двигателями (поздняя активация).
    `lua/qra.lua` раз в 10 с ищет ЛА противника ближе 200 км к базе и спрашивает радары своей стороны (РЛС, РЛС ЗРК,
    ДРЛО): цель видна радаром — звено взлетает, идёт в зону в 30 км от базы к фронту, атакует воздушные цели ближе
    80 км, 40 мин дежурит и садится. Низко, вне радаров — не взлетит.
  * **Вне миссии** дежурные силы противника ближе 150 км к цели удара ИИ снижают его успех на 5% и повышают
    вероятность потерять борт на 4% (`QRA_P`, `QRA_LOSS`). ОЦЕНКИ.
* **КРУ (GCI):** в DCS наведением пользуется только игрок на МиГ-29, поэтому КРУ стоит у аэродромов красных, где
  базируется МиГ-29 — у стоянок (150 м от средней стоянки в сторону от центра аэродрома). Свой канал, радиус 250 км;
  включён с начала (`ActivateGCI`), каналы — в брифинге («Наведение»). КРУ — часть модели: уничтожается,
  восстанавливается как ЗРК, бюджет миссии его не трогает.

### ДРЛО и заправщики

Части с ролями `awacs`, `tanker` (театр всей карты: E-3A — Нёрфених, KC-135 — Рамштайн, А-50 — Темплин; ОЦЕНКИ) — как
все авиачасти (база, потери, пополнение). Задача «дежурство» (`method: orbit`, `ai_only`): зона над своей территорией
за серединой линии фронта в `standoff_km` (ДРЛО — 150 км, заправщик — 200 км; ОЦЕНКИ). В каждой миссии вне лимита
групп ИИ, «ипподром» с начала миссии, задача DCS AWACS / Tanker; смены — по плану. Заправщики — только у синих: у ОВД
заправщиков для фронтовой авиации не было (Ил-78 — с 1987, для дальней авиации).

### Пригодность типа ЛА для задачи

`aircraft.json`: `fit` — оценка типа по видам задач (0..1, ОЦЕНКИ): `cas`, `interdiction` (колонны, пути подвоза),
`strike` (объекты тыла, позиции ЗРК), `sead`, `air`. Сравнивается с лучшим из тех, кто есть в кампании у обеих
сторон (`redfront/fitness.py`): эпоху задаёт состав сил (Су-25 рядом с A-10 — 0.85, без него — 1.0).

* Выбор исполнителя: относительная оценка минус 0.15 за каждую задачу, уже выданную его типу и полку в этом плане;
  ниже 0.3 — не назначается. Подавление ПВО — по `sead`, прикрытие — по `air`.
* Итог удара ИИ вне миссии — с множителем 0.6 + 0.4 × оценка.
* Тип без `fit` — без учёта типа; у типа с оценками нет нужного вида — для задачи не годится (F-15C по объектам тыла).

### Подвески

1. **По задаче** (`build.loadout_cats`): удар по аэродрому — runway, по ЗРК — DEAD, по колонне — BAI, по складу и
   мосту — strike, прикрытие — CAP; подавление ПВО — SEAD, прикрытие ударной — escort; затем категории доктрины.
   Источник — подвески **DCS Retribution** (`data/payloads.json`, 225 типов, LGPL-3.0, `data/PAYLOADS_NOTICE.md`,
   импорт `tools/import_payloads.py`). **Свои подвески** (`data/payloads_custom.json`, тот же формат) — первыми и
   заменяют одноимённую подвеску Retribution (например, Су-25 CAS: 2 Х-25МЛ, 2 ОФАБ-250-270, Б-8М1 С-8КОМ, 2 Р-60М).
   Нет у типа — загрузка DCS по умолчанию.
2. **Обязательные дополнения** (`weapons.fixups`): у Су-24М с ПРР — контейнер Л-081 «Фантасмагория» на пилоне 5 (без
   него ПРР не пускаются); F-4E — HARM на пилонах Shrike (см. выше).
3. **По году кампании** (`redfront/weapons.py`): берётся первая подвеска, где всё оружие есть на год кампании; иначе
   оружие новее года меняется более старым той же роли, которое несёт этот пилон (AIM-120 → AIM-7 → AIM-9, AGM-65G →
   D → B, GBU-38 → GBU-12 → Mk-82, CBU-97 → CBU-87 → Mk-20, R-77 → R-27, Х-31П → Х-58, ALQ-184 → ALQ-131, 9М120
   «Атака» (с 1996) → 9М114 «Штурм» ...), иначе пилон пуст. Годы — оценки по открытым данным. Допущение: в DCS есть
   только AGM-88C — он изображает HARM A/B с 1985. Что заменено — в брифинге («по году: ...»).
4. **Выбор командующего:** в редакторе вылета — «по задаче (автоматически)» или любая подвеска Retribution типа;
   выбранная по году меняется так же.

### Связь

`comms.py`; частоты условные, ОЦЕНКА. Сети: тактическая группа (все группы пакета игрока на одной частоте), ДРЛО
(А-50 / E-3A), аэродромы вылета и посадки (частоты УВД DCS), аварийная. Красные — МВ (124–138 МГц: Р-862, Р-863,
Р-832), синие — ДМВ (250–264 МГц: ARC-164, ARC-51).

У ЛА игрока каналы прописаны в радиостанции в .miz: К1 — тактическая группа, К2 — ДРЛО, К3 — аэродром вылета, К4 —
аэродром посадки, К5 — аварийная (в полосе станции; у F-16 — и на МВ). У типов без каналов в DCS (FC3) — частоты в
брифинге. В брифинге — карточка связи и позывные групп пакета; сообщения скриптов (подавление начало пуски, удар
отменён) — текстом своей стороне.

## Доктрины

Пакет доктрины — `redfront/data/doctrine/<пакет>.json`, выбирается на сторону (`--doctrine SIDE=PACKAGE`).

| Пакет | Сторона | Что |
|---|---|---|
| `wp` | красные | Варшавский договор; «Тактика ВВС», РЛЭ Су-25 и др. |
| `nato` | синие по умолчанию | НАТО на Центральном фронте 1970–1990; генерирует `tools/gen_nato.py` |
| `generic` | любая | общий профиль (`--doctrine blue=generic`) |

**Структура задачи** (основные поля): `title`, `performers` (роли), `target`, `method`, `strike` (ударная группа:
`size`, `maintask`, `loadout`), `support` (группы обеспечения: `size`, `lead_min`, `when`), `speed_kmh`, высоты
(`transit_alt_m_agl`, `attack_alt_m_agl`, `low_alt_m_agl`, `medium_alt_m_agl`), `ip_offset_km`, `package.rv_km`,
`escort`, `joint_heli`, `jtac`, `ai_only`, `from_year`, `depth_km`, `nations`, `source` / `method_source`,
`estimate_fields`. Уровень пакета: `apportionment`, `nation_bonus`, раздел `sim` (наземная модель, снабжение,
FARP, ночь, ремонт ЗРК), пояснения `*_note`.

### Доктрина НАТО

`data/doctrine/nato.json` (генерирует `tools/gen_nato.py`) по источникам: RAND R-3385-AF (D. Stein, «The Development
of NATO Tactical Air Doctrine 1970-1985», 1987), ATP-27(C) «Air Interdiction and Close Air Support» (1999), AJP-3.3(B)
(2016, формат распределения сил), FM 100-103 (1987), FM 101-20 (1984). Страницы — в полях `source` /
`method_source`. Высоты, скорости, размеры групп — оценки.

* **Задачи**: CAS (до FSCL, ~20–30 км), **BAI** — колонны в 15–50 км (ATP-27(B), с 1980; приоритет NORTHAG), DCA, OCA,
  удары по ЗРК, **FOFA** — вторые эшелоны в 50–150 км (директива SACEUR 1983; глубина — оценка), пути подвоза, мосты,
  склады. Задачи, которых ещё нет на год кампании, не планируются (`from_year`).
* **Распределение сил** (`apportionment`): DCA / OCA / SEAD / APCLO — не больше своей доли плана (формат AJP-3.3; доли
  — оценка: поддержка войск 50%, с 4-х суток 60%).
* **SEAD**: у союзников — обеспечивающее действие без своих средств; группа SEAD — только из частей США (F-16, F-4G),
  иначе пакет идёт без неё («быстрее и ниже»); с 1990 — Tornado ECR/ALARM.
* **Национальные предпочтения** (`nation_bonus`): Великобритания, ФРГ, Бельгия, Нидерланды (2-е ОТАК) — CAS и BAI;
  США (4-е ОТАК) — господство в воздухе, удары в глубину, SEAD. Величины — оценка.
* **Высоты** (FM 100-103, рис. 2-5, LLTR/MRR): к цели на 30 м (100 футов), отход — на 150 м; ИИ DCS — не ниже 100 м.

## Составы сил и театр

### Театры

* **Гамбург** — `sector_hamburg.json` + `oob_hamburg.json` (по умолчанию в консоли): цели операции — Люнебург, Винзен,
  Зольтау; варианты `base`, `uelzen`, `blue_early`; резервы — синяя танковая бригада (день 4), красный танковый полк
  второго эшелона (день 5).
* **Вся карта** — `sector_germany.json` + `oob_germany*.json` (генерирует `tools/gen_germany.py`): внутригерманская
  граница от Любека до Хофа, 113 пунктов, 44 военных аэродрома, ~30 дивизий ОВД и ~60 бригад НАТО с подкреплениями,
  авиаполки, пояс HAWK/Patriot. Источник гарнизонов и авиации — OOB-миссия Germany_OOB_1989 (поле `source`);
  составы бригад НАТО, сроки ввода резервов, оси, типы-заменители — ОЦЕНКИ. Красные наступают по 8 осям. Окно:
  «Новая» → «Театр». Зонды карты и дорог — свои для театра (`map_germany.json`, `roads_germany.json`).

### Объектовая ПВО

Позиция — место и ярус (`ad_sites` в `sector_germany.json`: long / medium / short); что на ней — шаблон стороны
(`ad_templates` в `oob_germany.json`), часть создаётся при `new`. Правила (`tools/gen_germany.py`, ОЦЕНКИ): ПВО
объекта (Оса/ЗСУ-23-4 или С-60; Roland/Gepard) — у каждого военного аэродрома; у красных — сеть С-75/С-125 (позиция
не дальше 35 км от каждого аэродрома и пункта, не у самой границы) и С-200 в глубине; у синих — пояс HAWK/Patriot.
Идея ярусов — из миссии-фреймворка Cold War Germany; позиции и типы не скопированы. Позиции — не на аэродромах и не в
городах: у аэродрома — в 5 км к фронту, у пункта — в 3 км к фронту, С-200 — в 4 км в тыл, не ближе 3 км к любому
аэродрому. Позиции берутся из файла сектора при каждой загрузке.

За сутки (`logistics.air_defence`, ОЦЕНКИ): потери ЗРК восстанавливаются на `repair_sam` (× промышленность и
снабжение; приданная ПВО части в бою — нет). Объектовая ПВО (`fixed`) позицию не меняет. Задача «Удар по позиции
ЗРК» (`strike_sam_site`): цель — исправная позиция объектовой ПВО; по приоритету — после ударов по аэродромам.

### Пресеты по годам

* `oob_germany.json` — 1989 (1 сентября, после ротаций июля 1989), по умолчанию;

### Добавить полк, перебазировать

«Авиация» → «Добавить полк» (`redfront/reinforce.py`), в любой момент:

* **из списка** — авиачасти других пресетов того же театра, которых нет в кампании (историческое допущение):
  например, 116-й гв. и 497-й бап (Су-24М) ушли из Германии в июле 1989 и в пресете 1989 отсутствуют; аэродром — свой
  из пресета (занят противником — ближний свой);
* **свой полк** — название, сторона, роль, тип ЛА (любой ЛА pydcs), число ЛА, аэродром (вертолётам — и площадка),
  радиус (пусто — по роли, иначе ОЦЕНКА 300 км, вертолёты 150).

В окне у части пометка «допущение» или «свой». В план — со следующих суток.

«Авиация» → своя часть → «Перебазировать»: свои открытые аэродромы с местом (16 мест на полк; вертолётам — и
площадки), с удалением до противника. Приказ выполняется в конце суток, его можно отменить.

## Проверено / не проверено

* **Без DCS:** .miz собирается и заново читается pydcs; Lua-хук исполняется интерпретатором Lua с заглушками DCS API и
  пишет корректный JSON; потери и продвижение применяются; второй день строится (`tools/smoke_test.py`). Другой тип с
  той же ролью (A-10A) планируется и собирается; сторона без пакета доктрины даёт причину вместо задачи. Тест проходил
  на машине с DCS (Python 3.15, без lupa): загрузки DCS по умолчанию, ливреи из Saved Games.
* **В DCS проверено:** хук пишет файл в `Saved Games\DCS\redfront`, потери и посадки фиксируются, миссия завершается
  штатно; колонна едет; Patriot, развёрнутый на ось угрозы, ведёт пуски; перекладка колонны на дорогу работает
  (группа заменяется с тем же groupId); тактическая группа летает. Без дорог колонна в поле в DCS рассыпается.
* **В DCS не проверено:** зонд дорог (проверен только с заглушками `land.*` / `coalition.addGroup`); схема
  подавления ПВО двумя парами с рубежом пуска и малой высотой в зонах; ПВО колонны (Gepard, Roland) и Patriot в
  глубине. Изменения состава сил попадают только в новые кампании (`new`).

## Заимствования и лицензии

* Подход «хук в миссии пишет JSON, приложение его читает» и примечание про `DoScript(String(...))` — из
  [SQE](https://github.com/MarkuzJuniuz/SQE) (MIT, MarkuzJuniuz). Код написан заново.
* Механика CSAR (маяк ADF, дым и ракета по запросу, пилот бежит к вертолёту, лебёдка, доставка на аэродром) — по
  мотивам [DCS-CSAR](https://github.com/ciribob/DCS-CSAR) (ciribob). Лицензии в репозитории нет, поэтому код не
  копируется: `lua/csar.lua` написан заново и без MIST.
* [DCS-CTLD](https://github.com/ciribob/DCS-CTLD) (Ciribob, Zip, VEAF; «free of use… publish a fork… credit
  appreciated») и MIST из его поставки (Speed, Grimes, lukrop) лежат в `redfront/lua/ctld/` без изменений; источник и
  версии — `redfront/lua/ctld/NOTICE.md`.
* Идея боя в соприкосновении — скрипт Troops in Contact (Grendel, MIT); код свой.
* Подвески — DCS Retribution, LGPL-3.0 (`redfront/data/PAYLOADS_NOTICE.md`).
