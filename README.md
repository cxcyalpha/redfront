# redfront (рабочее название)

Генератор динамической кампании для DCS World на карте Cold War Germany. Версия 0.2: одна колонна, одна задача,
одна авиачасть, но полный цикл «модель → задача → миссия → вылет → дебриф → следующий день».

## Три слоя

Игрок выбирает сторону, а с ней поведение ИИ и логику фронта. Техника — его дело.

| Слой | Файлы | Что в нём |
|---|---|---|
| Доктрина стороны | `redfront/data/doctrine/<пакет>.json` | задачи, исполнители по ролям, профиль полёта, порядок марша, пороги. Пакеты: `wp` (Варшавский договор), `generic` (сторона без доктрины: задач не планирует) |
| Состав сил | `redfront/data/oob_hamburg.json` или свой файл | любые типы, которые знает pydcs (имя класса или DCS id), у каждой части роль; страны сторон |
| Сектор | `redfront/data/sector_hamburg.json` или свой файл | места и аэродромы |

Связующие таблицы: `roles.json` (роли и категории: air / heli / ground / sam) и `loadouts.json` (тип → категория
подвески → пилоны; если записи нет, остаётся загрузка DCS по умолчанию для задачи).

Откуда берутся числа планировщика: радиус авиачасти — `strike_radius_km` у части, иначе у роли; радиус ЗРК —
`threat_radius_km` у части, иначе у роли, иначе наибольший `threat_range` пусковых из pydcs (это дальность по
высотной цели, против маловысотной она завышена).

Типы модов (Су-24, МиГ-31 и др.) pydcs пока не знает — их регистрация отдельный шаг.

## Принцип

Модель кампании — «карты и стрелочки»: части с численностью по типам, состоянием и маршрутом.
В миссию попадает только окно вокруг вылета:

1. **район задачи** — цель разворачивается куском части по шаблону построения;
2. **коридор маршрута** — ЗРК, которые достают маршрут;
3. **остальное** — не появляется.

**Правило сохранения:** развёрнутая машина несёт вес = исправные машины этого типа в модели / развёрнуто этого типа.
При любой плотности (`--density`) потери в DCS возвращаются в модель честно.

## Модули

| Модуль | Файл | Что делает |
|---|---|---|
| Модель | `redfront/model.py` | слои данных, роли, пакет доктрины по стороне, численность, маршрут, сохранение |
| Типы | `redfront/dcstypes.py` | поиск типа pydcs по имени класса или DCS id, дальность ЗРК из pydcs |
| Сутки | `redfront/sim.py` | марш колонны, остановка при потере боеспособности (порог из пакета её стороны) |
| Планировщик | `redfront/planner.py` | задача для стороны игрока по её пакету: исполнители и цели по ролям, ИПМ, угрозы в коридоре |
| Материализация | `redfront/materialize.py` | колонна по порядку марша её стороны, позиция ЗРК, веса |
| Сборка | `redfront/build.py` | .miz через pydcs: звено, наземное окно, хук; страны сторон переносятся в нужную коалицию |
| Хук | `redfront/lua/debrief_hook.lua` | пишет потери/посадки/позиции колонны в JSON |
| Дебриф | `redfront/debrief.py` | JSON → потери и продвижение в модели |

**Все числа — оценки и заглушки** (в данных помечены `"estimate": true`): составы, темпы, радиусы, подвеска,
высоты, порядок следования. Координаты населённых пунктов приблизительные — проверить в редакторе.

## Установка (Windows)

Нужны Python 3.11+ (при установке отметить «Add python.exe to PATH») и Git (pydcs ставится из GitHub).
В PowerShell в папке проекта:

    py -m venv .venv
    .venv\Scripts\python -m pip install -r requirements.txt
    .venv\Scripts\python tools\smoke_test.py             # тест двух дней без DCS

`.venv\Scripts\python` вызывается напрямую: активация `Activate.ps1` не нужна (на многих системах её блокирует
политика выполнения скриптов).

Необязательно, для полной проверки Lua-хука в тесте: `.venv\Scripts\python -m pip install -r requirements-dev.txt`
(ставит lupa). Если pip не может её собрать — пропустите: тест идёт и без неё, пропуская 4 проверки хука.

Тот же тест под pytest - каждый раздел отдельным тестом: `.venv\Scripts\python -m pytest -q` (нужен
`requirements-dev.txt`). На GitHub он идёт сам на каждый push и pull request (`.github/workflows/tests.yml`).

## Цикл

    .venv\Scripts\python -m redfront new     camp.json [--side red|blue] [--oob my_oob.json] [--doctrine blue=generic]
    .venv\Scripts\python -m redfront plan    camp.json
    .venv\Scripts\python -m redfront build   camp.json day1.miz [--density 1.0] [--ai]
    # летаете day1.miz в DCS
    .venv\Scripts\python -m redfront debrief camp.json        # файл дебрифа ищется сам в Saved Games\DCS*\redfront
    .venv\Scripts\python -m redfront end-day camp.json
    .venv\Scripts\python -m redfront status  camp.json

### Тактическая группа

Задача ставится тактической группой ('Тактика ВВС' 3.3.3): ударная группа и группы обеспечения из пакета доктрины
(`strike` и `support` у задачи в `data/doctrine/wp.json`). Сейчас: группа подавления ПВО - если в коридоре есть ЗРК
(обязательна: без неё удар не ставится); группа доразведки - если цель на марше. Исполнители выбираются по ролям,
с учётом числа самолётов и радиуса. Игрок по умолчанию - ведущий ударной группы (своим звеном до 4 ЛА командует сам),
остальные звенья - ИИ с рассчитанной задержкой взлёта. Другая группа: `build ... --fly sead` или `--fly recon`.
Основная задача DCS - первая из списка доктрины, которую тип умеет (у Су-25 нет SEAD - будет Ground Attack);
подвеска - первая категория из списка, найденная в `loadouts.json`, иначе загрузка DCS по умолчанию.
Размеры групп, упреждения и время холодного старта - оценки.

Группа подавления ПВО - две пары, у каждой своя задача. Рубеж пуска ПРР - на
`min(standoff_km, дальность обнаружения РЛС ЗРК - detect_margin_km)` от места, где ЗРК будет к приходу группы
(ПРР наводится на излучение: рубеж должен быть в зоне обнаружения РЛС). Подход на предельно малой высоте, на рубеже -
круг ожидания (центр отодвинут к базе на `orbit_radius_km`) на высоте `launch_alt_m` до времени удара +
`hold_after_min`, с задачей EngageGroup на всё ожидание: РЛС войсковой ПВО в DCS включаются при подходе ударной
группы. Если рубеж внутри зоны поражения (Patriot) - ожидание на малой высоте. Затем уход.
Скорость колонны для прогноза - замеренная в прошлых миссиях (`observed_kmh`, пишет дебриф); без замера колонна
считается стоящей. Все точки маршрута внутри известных зон ЗРК - на `low_alt_m_agl` (50 м). Ударная группа,
доразведка и подавление ПВО - с запретом сброса подвески. Всё это - оценки (`estimate_fields` в доктрине).

Пузырь: в миссию ставятся все ЗРК противника не дальше `settings.bubble_km` (150 км, ОЦЕНКА) от маршрутов пакета,
даже если до маршрута не достают - они стреляют и светятся на СПО, но группа подавления на них не назначается.

Огонь по ЛА ведёт только ПВО (роли `sam_*`); остальные наземные группы - только по наземным целям
(`OptRestrictTargets`, ставится в .miz и заново после перекладки колонны на дорогу). Войсковая ПВО части
(`attached_to` в составе сил) идёт отдельной группой в колонне сразу за танками.

### Фронт и план дня

Наземная модель (`sim.py`, коэффициенты - раздел `sim` пакета доктрины, все ОЦЕНКИ): части идут по маршрутам
до соприкосновения (`contact_km`), в соприкосновении за сутки несут потери по соотношению сил (техника с весами ролей;
у обороняющейся меньше), ниже порога боеспособности выходят из боя; противник продолжает марш. Дошедшая до конца
маршрута часть занимает район (оборона). Приданная ПВО несёт потери вместе с частью.

`plan` печатает план дня - список задач по приоритету доктрины (сначала войска в соприкосновении, затем колонны);
`build ... --task N` - какую задачу летит игрок (по умолчанию 1). Миссия по войскам в соприкосновении ставит весь бой:
обе стороны боевыми порядками в дальности огня друг друга, ПВО при частях позади; потери в миссии идут в модель.

Бой в миссии ведёт `lua/front.lua` (идея - скрипт Troops in Contact, Grendel, MIT; код свой, без MOOSE). Части в бою
стоят взводами по 4 машины (отдельные группы, имена машин из модели). Сами взводы огонь не ведут: скрипт даёт им
короткие окна огня в точку в 25-80 м от случайной машины противника в дальности их оружия - бой шумный, потерь мало
(их считает модель). Опцию "цели только наземные" скрипт не трогает: по самолётам стреляет только ПВО. Наступающий
выходит на рубеж огня и при потерях в миссии ниже 60% отходит на исходную; обороняющиеся взводы понемногу сдвигаются.
Невидимости, как у TIC, нет - ИИ-самолёты видят цели. Все числа - ОЦЕНКИ (`build.FRONT_CFG`).

Расстановку по местности делает `lua/battle_site.lua` в начале миссии (pydcs рельефа не знает): весь бой сдвигается
в пределах 2,5 км туда, где под позициями меньше воды, склонов и застройки, затем каждая машина - в лучшую точку рядом
(дорога > у дороги > поле > застройка; вода и склон исключены). Взводы пересоздаются с теми же именами и groupId.
Выбранное место пишется в файл дебрифа, модель его помнит (`battle_sites`) - в следующих вылетах бой там же.
ПВО на позициях (ЗРК и ЗА частей в бою, ЗРК в коридоре и пузыре) тот же скрипт ставит на открытое место:
поле, можно у дороги, не на дороге и не в застройке; не теснее 80 м; сдвиг до 400 м.
Лес скрипту DCS не отдаёт. Все веса - ОЦЕНКИ (`build.SITE_CFG`).

### Наземная модель по часам

Наземный мир идёт за часами кампании, а не сутками целиком (`sim.advance`): шаг - 1 ч, бой и марш за шаг - 1/24
суточной нормы (потери и суточный отрыв делятся на часы, сила пересчитывается каждый час), занятие пунктов - каждый
час, решения командования - в 00, 06, 12 и 18 ч (восстановление в тылу - за 6 ч). Снабжение, ремонт, пополнение,
судьба сбитых экипажей - раз в сутки, в их конце.

* **Миссия видит мир на своё время.** Сборка вылета продвигает модель к началу миссии (по плану полётов) и переносит
  цель задачи и маршруты групп на место цели к этому времени (`planner.refresh`, и у групп ИИ). Модель назад не идёт:
  вылеты раньше времени обстановки из плана дня уходят. Время обстановки - в окне ("День N, обстановка на ЧЧ:ММ").
* **Окно слетанной миссии.** Бой и марш в нём прошли в DCS (дебриф их применил) - модель после дебрифа проходит окно
  только событиями плана полётов, без боя и марша; дальше - как обычно.
* **Воздушная война вокруг игрока** (`airwar.py`): каждый вылет плана суток даёт итог в своё время на цели. Удар ИИ
  по колонне, части в бою, позиции ЗРК, объекту тыла, не слетанный в миссии: удача - 70% минус 10% на ЗРК в коридоре;
  потери цели - 4% техники на пару (позиция ЗРК - 25%), объекту тыла - повреждение 25-50%. Группа теряет борт с
  вероятностью 3% на ЗРК коридора; экипаж катапультируется (70%) - на земле у цели, его можно спасать (CSAR).
  Высадки десанта, спасение, удары по путям подвоза - тоже в своё время. Группы ИИ, бывшие в слетанной миссии
  (`played`), итога вне миссии не получают - их итог в DCS.

Марш и бой идут и ночью (часы 20-06 - без вылетов); всё - ОЦЕНКИ.

### Дежурные пары ПВО (QRA)

Задача `qra` доктрины (обе стороны, только ИИ): пара истребителей в готовности на 3 аэродромах с истребителями,
ближних к фронту, сменами по 4 ч весь лётный день; самолёты на смене заняты в плане суток.

* **В миссии** пары, чья база не дальше 300 км от цели задачи, стоят на стоянке с запущенными двигателями (поздняя
  активация). `lua/qra.lua` раз в 10 с смотрит самолёты и вертолёты противника ближе 150 км к базе пары и спрашивает
  радары её стороны (РЛС, РЛС обнаружения и сопровождения ЗРК, ДРЛО): кто-то видит цель радаром - пара взлетает,
  идёт в зону в 30 км от базы к фронту, атакует воздушные цели ближе 80 км, 40 мин дежурит и садится. Низко, вне
  радаров - пара не взлетит. Кто поднят - в дебрифе; потери пары - как у всех групп.
* **Вне миссии** (`airwar.py`) дежурная пара противника на смене ближе 150 км к цели удара ИИ снижает его успех на 5%
  и повышает вероятность потерять борт на 4% (на каждую пару).

### Оперативный уровень

Сектор - граф пунктов (`places`, `links`) с владельцами; линия фронта - связи между пунктами разных сторон.
Раз в сутки командование каждой стороны (`ops.py`) ставит задачи своим частям по позе из пакета доктрины:
`offense` (красные) - свободные сильные части наступают на соседние пункты противника, ближние к цели операции
(`objectives` сектора, по порядку: Люнебург, Винзен, Зольтау); `defense` (синие) - занимают незанятые пункты фронта,
лишние сильные части возвращают пустые пункты. Ослабевшие части выходят из боя (разрывают соприкосновение), отходят
в тыл и восстанавливаются; пункт занят, если рядом часть стороны и нет противника. Резервы вводятся в свой день
(`arrives_day`: синяя танковая бригада - день 4, красный танковый полк второго эшелона - день 5).
Все коэффициенты - ОЦЕНКИ (раздел `sim` доктрины, `ops_note`). `status` показывает пункты сторон и линию фронта.

Случайность: при `new` выбирается вариант сценария (`variants` в составе сил: base, uelzen, blue_early) и разброс
сроков ввода резервов; в бою за сутки - разброс потерь, в наступлении - выбор направления с весами. Всё повторяемо по
`--seed`; `--variant NAME` - вариант явно; `--no-random` - без случайности. Коэффициенты - ОЦЕНКИ (`random_note`).

### Тыл: снабжение, мосты, аэродромы

Только военные аэродромы (список в `sector_hamburg.json`, по памяти о базах 1980-х - проверить). Противник ближе 30 км -
аэродром закрыт, эскадрильи перебазируются на ближний открытый свой; противник на аэродроме - потерян (к противнику не
переходит). Повреждение аэродрома - меньше самолётов к вылету. Склады в пунктах, снабжение - в тоннах (ниже). Мосты на
связях: разрушенный закрывает связи на 3 суток. Эскадрильи пополняются до штата. В плане дня - удары по мостам,
складам, аэродромам (обе стороны). Цели в миссии - объекты карты в районе объекта (`lua/targets.lua`, как "Assign as"
в редакторе): их гибель пишет хук, дебриф переводит в повреждение. Координаты складов и мостов - ОЦЕНКИ: поставить
на реальные склады/мосты карты. Все коэффициенты - ОЦЕНКИ (`logistics_note` в доктрине, `debrief.FULL_DAMAGE`).

### Снабжение в тоннах и воздушные перевозки

Одна величина - "снабжение", т (топливо и боеприпасы вместе). Все числа - ОЦЕНКИ (`supply_t_note` в доктрине, `sim`):

* **Склад** - запас `stock_t` из ёмкости `cap_t` (ёмкость складов стороны - `depot_days` = 10 суток её расхода в
  обороне, поровну). Повреждение склада уничтожает запас сверх ёмкости x (1 - повреждение): удар по складу - потеря
  тонн, не только "полоска".
* **Расход** части в сутки - исправные машины (с приданной ПВО) x `consume_t` по состоянию: бой 1.0 т, марш 0.5,
  восстановление 0.3, оборона 0.2 т на машину. Часть берёт со своих складов не дальше `supply_km` по своей
  территории; бой - первым. Получила долю нормы - сила между `supply_power_factor` и 1, марш - между `unsupplied`
  и 1. Авиация - `sortie_t` (4 т самолёт, 1.5 т вертолёт) на вылет плана полётов, со склада, до которого от аэродрома
  есть путь; аэродром без снабжения выпускает меньше самолётов.
* **Подвоз из тыла** (дороги и железная дорога, без колонн в миссии - пока) - `supply_inflow` = 2.5 x расход стороны
  в обороне в сутки: марш держится, бой съедает склады. Только на склады, до которых есть путь от пунктов входа (тыл
  сектора: `supply_entry` сектора или 3 своих пункта, дальних от фронта). Отрезанный склад (окружение, разрушенные
  мосты) получает снабжение только воздухом.
* **Воздушные перевозки** - задача `airlift` транспортной авиации (роли `transport`, `transport_helo`), только ИИ:
  склады ниже 90% запаса со своим аэродромом не дальше 40 км, отрезанные первыми; до 4 направлений, по 2 рейса в
  сутки, в плане полётов (ATO) рядом с остальными вылетами. Груз борта - `cargo_t` в `aircraft.json` (Ан-26 5.5 т,
  C-130 19, Ми-8 4, Ми-26 20, CH-47 10 ...). Рейс в окне миссии - в миссии (до 2 на сторону): взлёт со своей базы,
  посадка на аэродроме назначения, задача DCS Transport. Перехватили - сбитый борт груз не довозит (дебриф).
* В окне: запас складов (%, т, "отрезан") - на карте и во вкладке целей тыла, там же сводка "Тыл за сутки"
  (подвоз, воздухом, расход); у частей - доля нормы снабжения.

Объёмы перевозок малы рядом с подвозом по дорогам (десятки-сотни тонн против тысяч) - так и задумано: они решают
там, где дорог нет (окружение, разрушенные мосты), а цели для перехвата видны в миссиях. Склад без своего аэродрома в
40 км (например, передовой в Бойценбурге) воздухом не снабжается - высадка груза вертолётом на площадку - позже.

### Вертолётный десант

Десантные роты (роль `air_assault`, в составе сил всех пресетов Германии): три роты 35-й одшбр (Бранденбург,
Магдебург) у красных, две роты Fallschirmjägerbataillon 271 (Падерборн) у синих - ОЦЕНКИ (рота: 100 человек, в миссии -
24 фигуры пехоты). В резерве (`order reserve`) рота стоит в своём пункте, командование фронта её не двигает.

Задача `air_assault` доктрины (одна в сутки на сторону, в плане полётов наравне с ударами - игрок может вести её
сам на Ми-8 или UH-1H):

* **Куда.** Пункт противника в 8-50 км от своих, не соседний со своими, без его частей ближе 10 км. Лучший - тот,
  после взятия которого у противника больше всего складов отрезано от подвоза из тыла (связь со снабжением), затем
  ближний к цели своей оси. Площадка - в 2 км от пункта в сторону своих.
* **Чем.** Транспортные вертолёты: бортов = ceil(100 / десантников на борт) (`troops` в `aircraft.json`: Ми-8 24,
  Ми-26 80, CH-53 37, CH-47 33, UH-1H/UH-60 11), не больше 8; группы DCS по 4 борта, вторая волна - через минуту.
* **В миссии.** Вертолёты идут на малой высоте, садятся на площадку на 2 мин (Land) и уходят домой. Площадка в начале
  миссии переносится на ближайшее открытое место (`lua/lz.lua`: суша, без строений ближе 45 м, перепад не больше 4 м
  на 20 м; кольцами до 1.5 км), вертолётам ИИ маршрут пересчитывается на неё. Роты в .miz нет: каждый борт везёт свою
  долю фигур и высаживает её у себя (`coalition.addGroup`, имена - из модели, потери пишет хук). Борт ИИ высаживает
  сам, сев ближе 800 м к площадке; игрок - через меню F10 "Десант": "Загрузить десант" (на земле у своего аэродрома),
  "Высадить десант" (на земле ближе 800 м к площадке), "Площадка" (пеленг, дальность, дым). Сколько бортов высадили
  долю - в дебриф.
* **Итог** (конец суток, `assault.resolve`): своё - по дебрифу; ИИ - сбитые в миссиях плюс 15% на борт за каждый ЗРК
  в коридоре. Рота в сбитых бортах гибнет. Долетело меньше 40% роты - высадка сорвана, иначе рота держит пункт
  (`order airhead`): занимает его, если рядом нет противника, без снабжения слабеет; при потерях отходит.
  Пункт взят и есть снабжение со своих складов - соединилась со своими, дальше обычная часть.

Пока не сделано: эскорт Ми-24 и прикрытие истребителями (пакет из одной транспортной группы), лес при выборе площадки
(DCS не отдаёт деревья скрипту - только строения), высадка роты у групп ИИ чужой задачи в окне миссии (летят и
садятся, пехота не выходит).

### Экипажи и поиск-спасение (CSAR)

**Экипажи.** У авиачасти `crews` экипажей (штат - 1.2 на самолёт штата, `crew_ratio`); к вылету - не больше
экипажей. Пополнение - 1 экипаж в сутки до штата (`crews_per_day`). Самолёт сбит:

* без катапультирования - экипаж погиб;
* катапультировался - экипаж на земле (`downed`: точка, маяк ADF 200-1190 кГц), пока его не спасут. На своей
  территории выходит к своим на следующие сутки; на чужой - каждые сутки в плен с вероятностью 35%
  (`capture_per_day`), через 3 суток - пропал без вести;
* подобран вертолётом и доставлен на свой аэродром - снова в полку.

**Задача `csar`** (первая в плане дня - самая срочная, до 2 в сутки): свой экипаж не на своей территории, ближняя
вертолётная часть в радиусе. Игрок может лететь сам на Ми-8 или UH-1H; вылет ИИ вне миссии удаётся с вероятностью
70% минус 15% за каждый ЗРК в коридоре.

**В миссии** (`lua/csar.lua`, в каждой миссии - катапультироваться может любой):

* экипажи на земле из модели (в районе задачи - обеих сторон) и катапультировавшиеся в этой миссии (появляются у
  точки катапультирования); бессмертны и невидимы для ИИ - плен решает модель; пилот переносится на ближайшее
  открытое место (`lua/lz.lua`, до 800 м), вертолётам ИИ, летящим за ним, посадка пересчитывается туда;
* маяк ADF (AM, кГц; звук маяка - ресурс миссии); частоты - в задаче, в меню и в окне;
* вертолёт ближе 3 км - "слышу вас"; сесть ближе 300 м - пилот бежит к вертолёту; или зависнуть над ним ниже 20 м
  на 10 с - лебёдка; на борту - на свой аэродром. Вертолёт сбит с ним на борту - погиб;
* меню F10 "CSAR" у вертолётов игроков: список экипажей (пеленг, дальность, частота), ракета, дым у ближнего.

Дебриф: экипажи сбитых (по точке катапультирования из хука), спасённые и погибшие. В окне - экипажи частей
(вкладка авиации) и свои сбитые экипажи на карте.

### Меню

Окно кампании: `run.bat` (`python -m redfront gui`) - страница в браузере: карта сектора с фронтом, частями, ПВО и тылом, план дня, сборка миссии, дебриф, конец дня, зонд карты. Первый запуск `run.bat` сам создаёт `.venv`.

Текстовое меню: `run.bat menu` (или `python -m redfront menu [кампания.json]`): статус, план дня, сборка миссии (в Saved Games\DCS*\Missions),
дебриф, конец дня, новая кампания - вводом номеров.

### Весь театр в миссии

В миссии - весь фронт: район задачи игрока подробно, остальное реже (`materialize.theatre`): бои - боевыми порядками
(свой `front.lua`, своё место по местности для каждого боя), колонны на марше - на дорогах, части в обороне и в тылу -
позициями, ЗРК - полностью. Плотность вдали - 0,35 бюджета колонны, машина не "дороже" 3 машин модели (ОЦЕНКИ:
`FAR_DENSITY`, `MAX_WEIGHT`). В воздухе - план дня обеих сторон: до 3 своих групп ИИ (кроме пакета игрока; в
брифинге) и до 4 групп противника, по всему театру; рядом с объектом игрока - вокруг его удара, остальные - между
10-й и 60-й минутой (ОЦЕНКИ: `build.AI_FLIGHTS`, `MISSION_WINDOW_S`). Самолёты эскадрилий не расходуются сверх
наличия. Летит ударная группа задачи, без групп обеспечения. Время вне миссии (остаток суток) считает модель.

### Воздушная война

Истребители в составе сил (роль `fighter`/`interceptor`): красные МиГ-29 (Пархим), синие F-4 (Гамбург) и Tornado
(Целле) - типы, аэродромы, радиусы - ОЦЕНКИ сценария. В пакет удара добавляется группа прикрытия (зона 40 км над
целью на 3000 м на время удара + 5 мин), если истребители противника достают до цели. Новая задача "Прикрытие войск":
пара в зоне над своими частями в бою или на марше, 25 мин - её можно лететь самому (МиГ-29).
Авиация противника: генератор строит план дня и для противника (по его пакету доктрины) и ставит в миссию до 2 его
групп, чьи объекты в этой миссии или в 40 км от объекта игрока, в районе +-5 мин от удара. В брифинге - только
общее предупреждение; потери противника идут в модель. Все числа - ОЦЕНКИ (`build.ENEMY_*`, доктрина).

### Дороги

В pydcs дорожной сети нет; дороги знает только DCS (`land.findPathOnRoads`). Отдельных шагов не нужно:
если модель ещё не знает дорог участков, по которым идёт колонна, миссия в первую секунду сама перекладывает
колонну на дорогу (`lua/column_road.lua`: та же группа, те же имена машин и groupId) и пишет найденные пути в файл
дебрифа. После `debrief` модель их запоминает, и следующие миссии ставят колонну на дорогу сразу.
Если DCS дорогу не нашёл, колонна остаётся, где стояла (итог - строка в журнале дебрифа).

Дороги всего театра сразу - служебная миссия дорог (по всем связям графа): кнопка "Зонд дорог" в окне или
`roads-probe <out.miz> --sector sector_germany.json --oob oob_germany.json`, запустить в DCS, затем "Применить дороги"
(или `roads-apply camp.json <roads_*.json>`, `new ... --roads <файл>`). Новая кампания берёт дороги сама: из Saved
Games (`redfront\roads_<сектор>.json`), иначе из поставки (`redfront/data/roads_<сектор>.json`, если файл положен в
проект). Граф пунктов меряется по длине дорог, где они известны: пути снабжения, досягаемость складов (`supply_km`) и
путь частей - в километрах по дороге.

### Пути подвоза и колонны снабжения

Подвоз из тыла (снабжение в тоннах) идёт к каждому складу по своему пути - от ближнего пункта входа (тыл сектора)
по своей территории, по дорогам (`convoys.py`). Поток пути - сколько склад недополучил после расхода суток (в пределах
подвоза стороны), т/сутки; поток участка - сумма путей через него; грузовиков - поток / 8 т. В окне - свои пути
подвоза (слой "Пути подвоза", толщина - поток).

* **В миссии** на участках с потоком (от 30 т/сутки) ближе 40 км к цели идут колонны грузовиков обеих сторон (Урал /
  КамАЗ, M818 / Bedford / Land Rover): 4-16 машин - доля суточного потока, бывшая на участке во время миссии (10%), по
  дороге (`OnRoad`) к концу участка. Машина несёт вес - грузовиков потока на машину (правило сохранения).
* **Удар по путям подвоза** (`strike_supply_route`, обе стороны, до 2 в сутки): участок с наибольшим потоком в радиусе,
  пакет - как у удара (подавление ПВО, прикрытие по доктрине); в миссии - колонна на участке, атака по ней.
* **Итог.** Сожжённые машины - недовоз: вес x 8 т (дебриф); удар ИИ вне миссии удаётся с вероятностью 70% минус 10% на
  ЗРК в коридоре и даёт недовоз 15% суточного потока участка. В конце суток недовоз ложится на склады, чьи пути идут
  через участок (по доле потока), - в сводке тыла "колонны разбиты - недовезено".

**Хуку нужен разблокированный `io`/`lfs`** в `<DCS>\Scripts\MissionScripting.lua`
(закомментировать строки `sanitizeModule('io')` и `sanitizeModule('lfs')`; сделайте резервную копию; обновления DCS
возвращают файл). Папка Saved Games может называться `DCS` или `DCS.openbeta` — хук пишет в `lfs.writedir()`.

## Проверено / не проверено

* Проверено без DCS: .miz собирается и заново читается pydcs; Lua-хук исполняется интерпретатором Lua с заглушками
  DCS API и пишет корректный JSON; потери и продвижение применяются; второй день строится (`tools/smoke_test.py`).
  С составом сил по умолчанию результаты 0.2 совпадают с 0.1 (30 машин, 20 при плотности 0.5, 18.33 км за сутки,
  22 машины на второй день, 40 из 90). Другой тип с той же ролью (A-10A) планируется и собирается; игра за сторону
  без пакета доктрины даёт причину вместо задачи.
* Тест прошёл на машине с установленным DCS (Python 3.15, без lupa): загрузки DCS по умолчанию, ливреи из Saved Games.
* **Проверено в DCS (первый вылет):** хук пишет файл в `Saved Games\DCS\redfront`, потери и посадки фиксируются,
  миссия завершается штатно; колонна едет.
* **Найдено в DCS и исправлено:** РЛС Patriot смотрела на север при угрозе с востока - ни одной засветки за вылет.
  Теперь позиция ЗРК развёрнута на ось угрозы (`heading_deg` у части, иначе пеленг на ближайший аэродром противника).
  Повторно в DCS ещё не проверено.
* **Проверено в DCS (второй вылет):** Patriot, развёрнутый на ось угрозы, работает (пуски, ведомый сбит).
* **Дороги:** без дорог колонна стояла в поле и в DCS рассыпалась (подтверждено). Перекладка колонны в начале миссии
  и зонд дорог проверены только с заглушками `land.*`/`coalition.addGroup` - в DCS ещё не запускались. Главное, что
  надо проверить в DCS: что addGroup с тем же именем заменяет группу и сохраняет groupId (на него ссылаются задачи атаки).
* **Проверено в DCS:** перекладка колонны на дорогу работает (группа заменяется, на дороге 30 машин); тактическая
  группа летает.
* **Найдено в DCS (Tacview, день 2) и изменено, в DCS ещё не проверено:** пара Су-24М пустила 2 ПРР из 8 и вышла
  на Patriot; группы шли на 350-600 м в зоне ЗРК. Теперь - две пары, рубеж пуска, малая высота в зонах; Patriot
  отнесён в глубину (вне коридора), у колонны - войсковая ПВО (Gepard, Roland); не-ПВО не стреляет по ЛА.
  Изменения состава сил (Patriot, ПВО колонны) попадают только в новые кампании (`new`).

## Заимствования

Подход «хук в миссии пишет JSON, приложение его читает» и примечание про `DoScript(String(...))` взяты из
[SQE](https://github.com/MarkuzJuniuz/SQE) (MIT, MarkuzJuniuz). Код написан заново.
Механика поиска и спасения в миссии (маяк ADF, дым и ракета по запросу, пилот бежит к севшему вертолёту, лебёдка
при зависании, доставка на свой аэродром) - по мотивам [DCS-CSAR](https://github.com/ciribob/DCS-CSAR) (ciribob).
Лицензии в репозитории нет, поэтому код не копируется: `lua/csar.lua` написан заново и без MIST.


## Театр всей карты (v0.9)

`sector_germany.json` + `oob_germany.json` (генерирует `tools/gen_germany.py`): внутригерманская граница от Любека
до Хофа, 113 пунктов, 44 военных аэродрома, ~30 дивизий ОВД и ~60 бригад НАТО с подкреплениями, авиаполки,
пояс HAWK/Patriot. Источник гарнизонов и авиации - OOB-миссия Germany_OOB_1989 (поле `source` у каждой части);
составы бригад НАТО, сроки ввода резервов, оси наступления, типы-заменители DCS - ОЦЕНКИ.
Красные наступают по 8 осям (`objectives.red`, у части - `axis`), синие обороняются.
В миссии: район задачи подробно, части ближе 60 км - частично (до 24 машин), дальше - знаком присутствия
(4 машины), ЗРК - до 250 км от цели (materialize.py, все пороги - ОЦЕНКИ).
Окно: «Новая» → «Театр». Зонды карты и дорог - свои для каждого театра (`map_germany.json`, `roads_germany.json`).

### Объектовая ПВО и ЗРК за сутки

Кроме войсковой ПВО при частях, у театра всей карты есть объектовая ПВО на постоянных позициях. Позиция - место и
ярус (`ad_sites` в `sector_germany.json`: long / medium / short), без модели; что на ней стоит - шаблон стороны
(`ad_templates` в `oob_germany.json`), часть создаётся при `new`. Правила размещения (`tools/gen_germany.py`, ОЦЕНКИ):
ПВО объекта (Оса/ЗСУ-23-4 или С-60; Roland/Gepard) - у каждого военного аэродрома; у красных - сеть С-75/С-125,
покрывающая аэродромы и пункты (позиция не дальше 35 км от каждого, не у самой границы), и С-200 в глубине. Средний и
дальний ярус синих - пояс HAWK/Patriot из OOB-миссии. Идея ярусов - из миссии-фреймворка Cold War Germany; позиции и
типы не скопированы.

Угроза в коридоре маршрута: радиус ЗРК не больше радиогоризонта его РЛС по цели на высоте маршрута в зонах
(`low_alt_m_agl`, 50 м: ~42 км при антенне 10 м, рельеф не учитывается) - иначе С-200 или Patriot "достают" любой
маловысотный маршрут. В миссию ПВО объекта ставится ближе 100 км от цели (`materialize.SAM_KM_ROLE`), остальные ЗРК -
ближе 250 км.

За сутки (`logistics.air_defence`, раздел `sim` доктрины, ОЦЕНКИ): потери ЗРК восстанавливаются на `repair_sam`
(x промышленность и снабжение; приданная ПВО части в бою - нет); подвижный ЗРК, понёсший потери, на следующие сутки
уходит на `sam_relocate_km` в сторону тыла. Объектовая ПВО (`fixed`) позицию не меняет.
КРУ (пункт наведения, GCI): в DCS наведением пользуется только игрок на МиГ-29, поэтому КРУ стоит у каждого
аэродрома красных, где по составу сил базируется МиГ-29 (Мерзебург, Виттшток), рядом с ПВО аэродрома (3 км от
центра к фронту). У каждого свой канал, радиус 250 км; в миссии включён с начала (`ActivateGCI`), каналы - в
брифинге ("Наведение"). КРУ - часть модели: может быть уничтожен, восстанавливается как ЗРК, бюджет миссии его
не трогает.

Позиции ЗРК не ставятся на аэродромы и в города: у аэродрома - в 5 км от него к фронту, у пункта - в 3 км к фронту,
С-200 - в 4 км в тыл, и не ближе 3 км к любому аэродрому карты. В миссии `battle_site.lua` не ставит машины ПВО ближе
150 м к бетону аэродрома (ВПП, рулёжки, стоянки); если позиция на аэродроме или в воде - сдвигает её всю
(до 8 км); в городе (5 и больше строений ближе 150 м) - тоже. Леса DCS скрипту не отдаёт. Позиции объектовой ПВО в кампании берутся из файла сектора при каждой загрузке - исправления доходят и до
уже созданных кампаний.
Позиции объектовой ПВО есть только в новых кампаниях театра всей карты (`new`); восстановление ЗРК - и в старых.

### План дня: разнообразие вылетов

* Исполнитель задачи - сначала часть с меньшим числом задач в этом плане, затем ближняя: вылеты расходятся по
  полкам, а не достаются одной эскадрилье (раньше - 4 группы "Харриеров" противника за вылет).
* Нет угроз ЗРК в коридоре (с учётом радиогоризонта) - переход к ИПМ и отход на `medium_alt_m_agl` (4000 м, ОЦЕНКА):
  выше МЗА и ПЗРК; есть угрозы - как раньше, на малой высоте.
* Новая задача "Удар по позиции ЗРК" (`strike_sam_site`): цель - исправная позиция объектовой ПВО противника,
  ударная группа атакует её группу, подавление ПВО - по ЗРК коридора. По приоритету - после ударов по аэродромам.

### ДРЛО и заправщики

Части состава сил (роли `awacs`, `tanker`; у театра всей карты: E-3A - Нёрфених, KC-135 - Рамштайн, А-50 - Темплин;
базы и число - ОЦЕНКИ), как все авиачасти: база, число самолётов, закрытый аэродром - вылета нет, потери - через
дебриф, пополнение - до штата. Задача доктрины "дежурство" (`method: orbit`, `ai_only`): зона над своей территорией за
серединой линии фронта в `standoff_km` (ДРЛО - 150 км, заправщик - 200 км; ОЦЕНКИ). В план игрока не попадает; в
миссию ставится вне лимита групп ИИ, в воздухе в зоне с начала миссии ("ипподром" до конца), задача DCS AWACS / Tanker.
Заправщики - только у синих (пакет `generic`): у ВВС ГСВГ в 1989 г. дозаправки в воздухе не было.
Смены дежурства - по плану полётов на сутки (см. ниже).

### Боевые вертолёты

Части состава сил с ролью `attack_helo` (театр всей карты: полки Ми-24П при армиях ГСВГ - Пархим, Мальвинкель,
Брандис, Альштедт; PAH-1 бундесвера - Целле, Фрицлар, в DCS - SA342M; AH-64A армии США - Гибельштадт; части, базы и
число - ОЦЕНКИ, по памяти). Задача доктрины "Удар вертолётов по войскам в соприкосновении" (`cas_helo`): 220 км/ч,
переход на 60 м, атака с 30 м, ИПМ в 8 км; маршрут ниже 100 м и у ИИ (ограничение `AI_LOW_MIN_M` - только для
самолётов). Лететь можно самому (Ми-24П, SA342M).

В плане дня - не больше `MAX_PER_KIND` (2) задач одного вида: раньше у синих план мог состоять из 8 "прикрытий войск".

### Бюджет миссии

Наземных машин в миссии - не больше бюджета (по умолчанию 600, ОЦЕНКА; в окне - поле над планом дня, в консоли -
`build --budget N`, запоминается в кампании; 0 - без ограничения). Окно задачи игрока (цель, угрозы коридора, ЗРК у
маршрутов) не трогается. Остальное - по удалённости от маршрутов пакета и объекта, дальние первыми: сначала колонны
и боевые порядки прореживаются (меньше машин, вес машины больше - до 3 машин модели), затем дальние группы убираются
целиком (бой - со всеми участниками, колонна - с приданной ПВО, ЗРК - позицией). Убранное живёт в модели, в этой миссии
его нет. Без бюджета миссия театра к 8-му дню - до ~1200 машин.

### План полётов на сутки (ATO)

Вместо "магазина задач" - план полётов обеих сторон на лётный день (`redfront/ato.py`; 06:00-20:00,
`settings.flying_hours`, ОЦЕНКА). Задачи и пакеты - те же (цели, исполнители, группы обеспечения), к ним добавлено
время: задачи стороны по порядку приоритета ставятся равномерно по лётному дню; вылет ставится, только если у части
хватает самолётов на всё время вылета плюс подготовку к повторному (`turnaround_min` доктрины, по умолчанию 90 мин),
иначе позже, шагом 15 мин. Дежурства (ДРЛО, заправщик) - сменами по 4 ч (`shift_h`) весь лётный день; не хватает
самолётов - в дежурстве разрыв. До 12 задач стороны на сутки, не больше 3 одного вида (ОЦЕНКИ).

Игрок выбирает вылет своей стороны из плана - по времени ("взлёт 09:01, на объекте 09:15"). Миссия начинается в
своё время суток (холодный старт до взлёта по плану) и длится окно `ato.MISSION_LEN_S` (75 мин). В миссии - вылеты
обеих сторон, которые в это окно в воздухе (своих не больше 3 групп, противника - 4, ближние по времени и месту к
удару игрока; дежурства - все): кто к началу уже летит к объекту - в воздухе на своём маршруте, кто позже - взлетает
по расписанию, смена дежурства сменяет предыдущую в зоне. После дебрифа часы кампании - конец миссии: в плане
остаются вылеты позже, слетанный не предлагается; конец дня - новый план.

План полётов виден во вкладке окна "ATO" (своя сторона; галочка "план противника (отладка)" - и противник) и в
консоли: `ato camp.json` (своя сторона), `--side enemy` / `--side all` - план противника (отладка).

Пока не сделано (следующие этапы): вылеты вне окна миссии модель не считает (их потерь нет); группы, которые к началу
миссии уже возвращаются, в миссию не ставятся; ночь; наземная модель по-прежнему с шагом в сутки (колонны в миссии -
в положении на начало дня, в любое время суток).

### Скорость ЛА и страны в миссии

Скорость группы на маршруте и в расчёте времени (план полётов, взлёт групп пакета) - крейсерская скорость типа
исполнителя из `redfront/data/aircraft.json`; тип без записи - скорость задачи доктрины (`speed_kmh`). Значения в файле
сейчас - ОЦЕНКИ; настоящие - `V_opt` ("Cruise speed (for AI)", м/с) из Lua-описаний ЛА вашей DCS:

    .venv\Scripts\python tools\dcs_cruise.py "C:\Program Files\Eagle Dynamics\DCS World"

(можно добавить вторым аргументом папку модов, например `Saved Games\DCS\Mods`); утилита перезаписывает типы, у
которых нашла V_opt, источник - имя файла.

Страны в миссии - Combined Joint Task Forces Red / Blue (в них есть вся техника и авиация); национальность частей -
в составе сил (`countries`), для модели и брифинга.

### Пресеты состава сил по годам

Авиация театра всей карты - по сводке игрока о ВВС в Германии (полки, базы, техника по годам; `AIR_HISTORY` в
`tools/gen_germany.py`, места с "?" - источники расходятся, в поле `source` части). Пресеты - состав сил на дату:

* `oob_germany.json` - 1989 (1 сентября, после ротаций июля 1989), по умолчанию;
* `oob_germany_1987.json` - 1987 (1 июня): МиГ-29 у 4 из 9 истребительных полков, Бранд на Су-24М;
* `oob_germany_1985.json` - 1985 (1 июня): МиГ-29 ещё нет, Су-25 нет.

Дата кампании - дата пресета. Исторического типа нет в DCS - ближайший (замена в имени части: МиГ-23М -> МиГ-23МЛД,
Су-17М3 -> Су-17М4, F-16A/C блок 15-30 -> F-16C блок 50, F-104G -> F-4E и т.п.). Число самолётов и радиус - ОЦЕНКИ.

Части с баз вне карты Cold War Germany **перебазированы** на аэродромы карты своей стороны - без воздушного старта и
влёта из-за края карты (за синих тоже должно быть играбельно). Правило (`relocate` в генераторе): ближайший к
